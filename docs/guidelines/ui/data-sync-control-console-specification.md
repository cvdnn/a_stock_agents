# 数据同步一级菜单三页控制台交互规范

> 适用范围：A-Stock Agents Web 投研端一级菜单【数据同步】、三页签控制台及其确定性系统配置交互
> 核心目标：建立与现有浅色金融界面一致、无 AI 助手依赖、真实数据驱动的数据同步运行控制与配置界面

## 一、定位与边界

【数据同步】是左侧导航中的一级功能菜单，与【投研助手】、【市场行情】、【自选个股】、【收益分析】和【技能治理】同级。该菜单承载行情数据同步系统的运行、追溯与配置能力，不属于 AI 投研对话场景。

页面必须满足以下边界：

1. 进入 `datasync` 后，数据同步工作区占满业务主区域，不展示伴随式 AI 助手。
2. 页面不得创建对话上下文、发送聊天消息、选择模型或触发任何模型调用。
3. 同步、取消、重试、保存设置等操作必须调用确定性系统接口。
4. 页面不得使用随机数、固定成功文案或延迟定时器伪造同步结果、健康度、链路延迟与任务进度。
5. 同步引擎、交易日历、SQLite 落盘与完整性校验逻辑仍以核心数据模块为单一真理来源，前端只负责呈现与调度。

## 二、与现有系统的视觉契约

本页面只调整信息架构，不建立独立视觉语言。所有新增组件必须复用 [`ui-design-guide.md`](./ui-design-guide.md) 和 `web/css/style.css` 的现有语义 Token。

| 界面层级 | 必须遵循的系统规范 |
|:---|:---|
| 左侧导航 | 复用现有 `190px` 白色侧栏；激活项使用 `var(--primary)` 蓝底与白色文字 |
| 工作区标题栏 | 高度 `50px`、白底、底部 `1px solid var(--border-card)` |
| 内容画布 | 使用 `#F8FAFD` / `var(--bg-canvas)`，保持现有滚动容器行为 |
| 卡片 | 白色或 `#FAFCFE`，`1px` 微边框，`8px` 圆角，复用轻量阴影 |
| 操作按钮 | 复用 `.btn-workbench-action`、主次按钮层级和现有 Hover / Focus 状态 |
| 状态色 | 正常/完成使用绿色，警告/停牌使用橙色，异常/缺漏使用红色，并配文字或图标 |
| 数值 | 股票代码、时间、耗时、延迟、百分比、条数均启用 `.tabular-nums` |
| 图标 | 新增结构性图标统一使用同风格描边 SVG，不使用 Emoji 作为按钮或导航图标 |

卡片和列表必须遵循 Zero-Stripe 原则，不得增加粗彩色左边框。页面动效限制在 `150–300ms`，并尊重 `prefers-reduced-motion`。

## 三、信息架构

数据同步控制台包含三个同级 Tab：

```text
数据同步（一级菜单）
├── 运行控制
│   ├── 服务状态与关键指标
│   ├── 分级同步任务
│   ├── 数据完整性
│   ├── 行情源健康度
│   ├── 自动守护摘要
│   └── 最近任务日志
├── 任务记录
│   ├── 任务统计
│   ├── 筛选工具栏
│   ├── 任务列表
│   └── 单任务详情
└── 高级设置
    ├── 基础同步策略
    ├── 定时守护
    ├── 数据源优先级
    ├── 完整性与自愈
    ├── 本地存储
    └── 外部协同
```

Tab 切换仅改变 `#pane-datasync` 内部的 `tabpanel`，不得改变一级菜单激活状态。当前 Tab、筛选条件和滚动位置应在同一浏览器会话内保持。

## 四、运行控制页规范

### 4.1 首屏结构

首屏采用“4 个状态卡 + 主次双栏”的结构：

- 状态卡依次显示服务状态、本地标的数量、最近同步时间和待处理异常数。
- 主栏承载分级同步任务与完整性概览。
- 右侧固定宽度次栏承载行情源健康度、自动守护摘要和最近任务日志。
- 页面顶部只允许一个主操作“同步选中范围”；“完整性体检”为次操作。

### 4.2 分级同步任务

分级同步任务按业务重要性展示：

| 标的层级 | 范围 | 默认定盘时机 | 展示要求 |
|:---:|:---|:---|:---|
| P0 | 持仓池 | 交易日 `15:35` | 标的数量、最新水位、同步状态和独立同步入口 |
| P1 | 自选与关注池 | 交易日 `15:40` | 标的数量、最新水位、同步状态和独立同步入口 |
| P2 | 核心指数 | 盘后定盘阶段 | 指数数量、最新水位、同步状态和独立同步入口 |

用户提交同步后，界面必须立即展示服务端返回的真实任务 ID，并根据任务状态接口刷新进度。请求期间按钮禁用，禁止重复提交。

### 4.3 数据完整性

完整性区域展示已审计标的、健康度、合规停牌和异常缺漏。合规停牌不得标记为异常缺漏。未执行审计或数据不可用时，必须展示明确空状态，不得显示示例数字。

完整性操作包括：

- 全库体检：创建真实数据同步审计任务。
- 靶向修复：只针对后端返回的真实缺漏创建修复任务。
- 查看明细：展示代码、名称、理论交易日、实际落盘、合规停牌、异常缺漏与处理状态。

### 4.4 行情源与守护摘要

行情源列表必须区分首选、热备、配额源与本地离线层，并展示最近一次真实探测结果。探测不可用时显示“未检测”，不得随机生成延迟。

自动守护摘要展示启用状态、P0/P1 执行时间和并发数。摘要中的值以服务端有效设置为准。

## 五、任务记录页规范

### 5.1 数据范围

任务记录页读取异步任务接口，并只展示 `task_type` 为 `data_sync` 或 `sync` 的任务。顶部统计由当前返回数据现场聚合，禁止硬编码。

### 5.2 筛选与列表

筛选项包括日期范围、任务类型、状态和任务 ID / 标的关键字。任务表格至少包含：

| 字段 | 说明 |
|:---|:---|
| 开始时间 | 使用本地时区显示，保持等宽数字 |
| 任务名称 | 根据参数映射为持仓、自选、指数、指定标的或完整性任务 |
| 同步范围 | 标的数、股池或代码摘要 |
| 模式 | 增量、全量、快照、审计或修复 |
| 结果 | 成功数 / 总数；不可用时显示 `—` |
| 状态 | 排队、运行、完成、失败、超时或已取消 |
| 耗时 | 使用服务端 `elapsed_ms` 转换 |
| 操作 | 详情、取消、重试或再次执行 |

### 5.3 单任务详情

选择任务后，详情面板展示任务 ID、触发方式、原始参数、创建/开始/结束时间、耗时、结果摘要和错误原因。

- `pending` / `running`：允许取消。
- `failed` / `timed_out` / `cancelled`：允许使用原参数重新提交。
- `completed`：允许再次执行。
- 活动任务存在时启用有限轮询；离开任务记录页或没有活动任务时停止轮询。

无任务时显示“暂无数据同步任务”，并提供返回运行控制页的确定性入口。

## 六、高级设置页规范

高级设置采用左侧配置域导航与右侧表单，不使用弹窗承载主配置流。

### 6.1 配置域

| 配置域 | 配置项 | 约束 |
|:---|:---|:---|
| 基础同步策略 | 默认模式、并发数、重试次数、超时秒数 | 并发数限制 `1–16`；超时与重试必须由服务端校验 |
| 定时守护 | 总开关、P0 时间、P1 时间 | 时间格式固定为 `HH:MM`；非交易日不得触发 |
| 数据源优先级 | 腾讯、新浪、东方财富、本地 SQLite 的顺序与启用状态 | 至少保留一个可用数据源；保存前展示影响范围 |
| 完整性与自愈 | 自动审计、异常缺漏自动回补 | 合规停牌不得触发回补 |
| 本地存储 | 数据库相对路径、WAL 状态、日志路径 | 只读展示；路径必须由工作区根目录解析 |
| 外部协同 | 通达信文件导入与目标股池 | 与基础同步策略分离；导入结果必须来自真实解析结果 |

### 6.2 保存与恢复

设置通过服务端白名单校验后保存到 `local/settings/data_sync.json`。路径必须通过 `scripts/core/workspace.py` 的 `LOCAL_DIR` 解析，不得硬编码绝对路径。

表单必须展示未保存状态。保存成功后以服务端回读值刷新；保存失败时保留用户输入并展示原因。恢复默认设置属于全局影响操作，必须二次确认。

定时守护每轮读取有效设置。总开关关闭时不得触发自动同步；新的时间和并发设置只影响后续任务，不中断正在运行的任务。

## 七、接口契约

### 7.1 复用的任务接口

| 方法 | 路径 | 用途 |
|:---:|:---|:---|
| `POST` | `/api/tasks` | 创建 `data_sync` 任务 |
| `GET` | `/api/tasks?limit={N}` | 读取任务记录 |
| `GET` | `/api/tasks/{task_id}` | 读取任务详情与进度 |
| `DELETE` | `/api/tasks/{task_id}` | 取消活动任务 |

### 7.2 数据同步控制台接口

| 方法 | 路径 | 返回职责 |
|:---:|:---|:---|
| `GET` | `/api/data-sync/overview` | 市场阶段、同步元数据聚合、股池数量、最近同步任务和设置摘要 |
| `GET` | `/api/data-sync/settings` | 服务端默认值合并后的有效设置 |
| `PUT` | `/api/data-sync/settings` | 校验并保存白名单设置，返回最终有效值 |

无数据时，概览接口必须返回 `null`、空数组和明确的可用性字段，不得返回演示数据。错误响应必须提供稳定错误信息，前端不得以成功状态掩盖失败。

## 八、交互状态与错误恢复

所有异步区域必须具备 `loading`、`empty`、`success`、`degraded` 和 `error` 状态：

- 超过 `300ms` 的加载显示骨架或局部进度反馈。
- 提交按钮在请求期间禁用并显示加载态。
- 成功、局部降级和失败统一使用系统右下角 Toast。
- 错误信息必须同时描述原因与恢复操作。
- 取消任务、关闭守护和恢复默认设置必须明确影响范围。
- 页面切换不得丢失用户筛选和未保存表单状态。

## 九、AI 隔离契约

1. `switchRightTab('datasync')` 必须保持业务工作区全宽，并隐藏 `#btnCopilotLauncher`。
2. 数据同步不得出现在 `TabCopilotConfigs` 中。
3. 数据同步页面不得调用 `askAboutRightContent`、`executeQuickAction`、聊天提交或模型选择逻辑。
4. 数据同步标题栏不得出现“AI 助手”“咨询”“研判”等操作。
5. 切换至其他业务菜单后，原有 Copilot 行为按各自规范恢复。

## 十、响应式与可访问性

- 桌面宽屏下，运行控制采用主栏 + `290px` 次栏；任务记录采用表格 + 详情栏；设置采用配置域导航 + 表单。
- 窄屏下，次栏和详情栏移动到主内容下方；配置域导航转为横向或双列导航。
- 数据表格可在自身容器内横向滚动，页面不得产生整体横向滚动。
- Tab 使用 `role="tablist"`、`role="tab"`、`role="tabpanel"` 与 `aria-selected`，支持方向键切换。
- 所有按钮具备可见的 `:focus-visible`，图标按钮提供 `aria-label`。
- 状态信息不得只用颜色表达；所有加载和错误消息使用适当的 `aria-live`。
