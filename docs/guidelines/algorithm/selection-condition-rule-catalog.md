# 智能选股系统 · 第一期条件选股规则目录与示例一覆盖评估

> 类型：产品规则目录与落地边界；整理日期：2026-10-12。关联 [智能选股系统规范](./selection-system-specification.md)、[模型通用设计规范](./selection-model-general-specification.md)、[漏斗示例一](./selection-funnel-example-1.md)、[数据同步规范](../data/market-data-sync-specification.md)。本目录规定一期**拟提供的意图和可核对口径**，不表示所有条件已接入运行数据或已成为正式信号。

## 1. 调研结论与一期取舍

用户提供的两张条件选股截图展示了两种常见入口：按技术、行情、基本面、财务、阶段表现、特色数据分组的指标菜单；以及按市场范围、上市时间、行业、地区、基本面、行情技术面等分组的选股器。这些是**产品分类参考**，不是本项目必须逐项复制的规则清单。

公开产品中，[东方财富选股器](https://datah5.eastmoney.com/Xuangu/index)同时提供股票范围、财务、估值、行情、股东股本和公告类条件；[同花顺 i问财](https://www.iwencai.com/school/article-detail/id/4869)展示了中文问句及基本面、消息面、技术面、概念的多条件组合；[通达信条件选股](https://help.tdx.com.cn/gspt/docs/markdown/tdxgs-gsxt/tdxgs-1d1kngjqe0gck.html)以可参数化技术形态筛选股票，其[条件关系说明](https://help.tdx.com.cn/gspt/docs/markdown/tdxgs-1d1olc9o6k8n8/tdxgs-1d1rhf62blj9o.html)明确区分 AND 与 OR。由此推导本项目一期应先建**可组合的规则能力目录**，而不是把菜单文案、指标算法、特定战法阈值混成一张固定模板。

一期分两圈：**A 圈必须完整表达并核对示例一的四层漏斗**；**B 圈收录市场上高频、数据口径相对清楚的通用条件**，但新增算法/字段只有通过规则注册、数据门禁和编译测试后才在工作台标为可用。财报、消息、概念、专有 DDE、机构画像等暂列后续。手工立即运行仍针对完整本地证券主数据全集，实际运行以交易日数据水位为门槛，不以已有日 K 股票数冒充全市场分母。

## 2. 规则目录的数据结构与自然语言契约

每个条件应在能力目录中声明：`intent_id`、中文名称及别名、`rule_type/version`、允许的字段 ID/运算符/参数及单位、取值时点与复权方式、阶段/证券范围约束、所需数据集和质量等级、缺失处理、输出证据字段。字段目录另声明来源、单位、交易日、可用时间和最终水位；**不能只因 `field_compare` 接受字符串字段，就将任意字段视为可筛选字段**。展示的中文条件与内部规则 ID 分离，以便增加新条件而无需改写旧策略。

LLM 使用项目“系统配置”中的 `quant` 角色模型，把用户原文拆为带原文片段位置的原子意图和 AND/OR/NOT 关系；服务端只接受目录内的字段、规则和参数，复核每个数字、比较符、单位、时间与阶段，再生成未激活草稿。未知条件或口径不完整时标记 `unresolved`；不能把“或”改成“且”，不能自选指数、默认阈值或资金流代理口径。发布前仍需人工核对、编译、数据校验和版本冻结。现有自然语言编译器主要支持少量盘后条件，跨 T/T+1 四阶段、完整布尔表达式属于待落地能力，不能因目录已收录就标为已实现。

统一状态采用四级，而不是单一“支持/不支持”：

| 级别 | 含义 | 工作台呈现 |
|---|---|---|
| 目录收录 | 有意图、语义与字段定义 | 可搜索，标明“待实现/待数据” |
| 规则注册 | 参数 Schema 与确定性计算器已注册 | 可编辑/预览，但仍查数据依赖 |
| 可观察运行 | 所需本地数据与水位通过，逐股有 PASS/FAIL/UNKNOWN 证据 | 可产生观察候选；失败关闭时无候选 |
| 正式信号 | 额外通过对应数据等级、回放和发布验收 | 才可标记为正式信号；一期不预设达成 |

## 3. A 圈：示例一必须覆盖的条件

以唯一可执行配置 [`config/funnel_strategy.yaml`](../../../config/funnel_strategy.yaml) 为示例取值来源；示例阈值和时间窗均可配置，不是新模型默认值。括号中的“已注册”只指 [`rule_registry.py`](../../../scripts/core/selection_models/rule_registry.py) 和 [`stock_funnel.py`](../../../scripts/core/strategy/stock_funnel.py) 已有规则类型，不代表本次验证了生产数据。

| 阶段 | 中文意图及示例取值 | 受控规则 | 数据前置和当前边界 |
|---|---|---|---|
| T 日盘后 `post_close` | 非 ST/退市风险名称；非北交所 | `text_exclude(name)`、`symbol_prefix_exclude(code)`；已注册 | 证券主数据 D1。示例采用名称词元和代码前缀派生，不能宣称等同权威历史 ST/板块分类。 |
| 同上 | 流通市值 **> 30 亿元**；当日涨幅 **< 7%** | `field_compare(circulating_market_cap/change_pct)`；已注册 | D7 市值统一为**元**，D2 涨幅为百分数；缺失不能按 0 判定。`<7%` 与“不超过 7%”的 `≤7%` 必须分别编译。 |
| 同上 | 收盘价创**此前完整 20 日**新高 | 应为 `close_new_high(closes,20,strict=true)`；已注册 | 前复权收盘价至少 21 根。示例 YAML 目前写 `rolling_high(20)`，实际仅比前 19 根；见 §5 的语义缺口，示例按原样运行不满足此精确定义。 |
| 同上 | 收盘价高于 MA60；MA60 较前一交易日向上 | `above_sma(60)`、`sma_slope(60,lag=1)`；已注册 | D2 足量且同一前复权序列；“向上”必须声明比较日数和严格性。 |
| 同上 | 今日成交量 > 昨日成交量 | `series_compare(volumes[-1],volumes[-2],gt)`；已注册 | D2 连续日线；不同于“持续放量”或“量比大于 X”。 |
| T+1 大盘门控 `market_gate` | 上证指数现价高于此前完成的 MA20 | `market_above_sma(benchmark=sh000001,period=20)`；已注册 | 指数历史日线 + 对应时点现价；指数与个股不能混淆。示例窗口 `09:30–09:35`，门控时点与规范的竞价前终判要求存在待核对差异。 |
| T+1 高开 `opening_gap` | 开盘相对昨收高开 **1%～2%**（闭区间） | `range(gap_pct,min=1,max=2)`；已注册 | D9 开盘/昨收同源且时间戳可追溯；不同于“高开 ≥1%”或“任何正高开”。窗口 `09:30–09:31`。 |
| T+1 回调确认 `turning_point` | 早盘回调后价格反转，`09:40` 窗口末收敛 | `intraday_turning_point`，`required=[pullback,price_reversal]`、`min_confirmations=0`；已注册 | 连续分钟点、足量点数与时间顺序。当前示例只启用价格形态；真实卖盘衰减/主动买量/五档优势属于 D11 供需确认，不可由形态版代称。 |

示例另有两项**已注册但默认关闭**：`volume_sustained_expansion`（近 N 日均量相对前 M 日均量）与 `main_net_inflow > 0`（主力净流入）。前者可在明确窗口/基线后选用；后者只有 D10 精算档对本次筛选全集达到 `finalized` 才能作正式硬条件，代理档只能用于观察或排序。示例 `ranking.top_n`、权重和 `risk_exit` 是 `status: declared`，不属于一期已执行筛选规则。

## 4. B 圈：第一期主要通用条件及激活次序

以下是**推荐首期目录**，不是声称现有引擎全部可运行。先开放复用 A 圈原语且有数据口径的项，再扩展常见技术指标。用户输入的新条件如果属于已注册的原语，只新增受控字段或参数映射；若需要新算法，则注册新版本和确定性求值器。

| 类别 | 一期主要意图与可配置参数 | 现有承载与所需工作 | 上线次序 |
|---|---|---|---|
| 证券范围 | 沪/深/北；主板/创业板/科创板；排除 ST/停牌；上市满 N 天 | `market_include`、名称/代码派生已有；板块、停牌、上市天数要有明确主数据及历史时点，禁止仅凭名称/代码推断全部状态 | A 圈范围先行；新增字段经 D1 验收 |
| 行情价格 | 收盘价/涨跌幅/振幅/成交额/换手率的比较或闭区间 | `field_compare`、`range` 已注册；逐字段白名单、单位、日线/实时口径和缺失策略待落实 | D2 字段逐个验收后开放 |
| 规模与估值 | 总/流通市值、PE、PB 的比较或区间 | 同上；D7 市值为元，PE/PB 需申明财报与行情计算口径，不把 `0` 当缺失 | 数据与字段目录验收后开放 |
| 趋势突破 | 收盘价与 MA(N)；MA 斜率；此前 N 日收盘新高/低；均线交叉 | 已有 `above_sma`、`sma_slope`、`close_new_high`；新低和交叉需新增明确规则与足量日线测试 | 先完成示例新高语义修正，再扩展 |
| 量能 | 今量/昨量、近 N 日均量/前 M 日均量、成交额、换手率、量比 | `series_compare`、`volume_sustained_expansion` 已有；“量比”须定义当日时点及同时间段基准，不能用今量/昨量代替 | 日频先行，盘中量比后置 |
| 市场环境与次日阶段 | 指数 MA 门控、开盘涨跌幅区间、回调后价格反转 | A 圈已有原语；时点、日历、分钟数据水位和阶段衔接需统一验收 | 与示例一同步 |
| 常用技术指标 | MACD 金叉/死叉、KDJ 交叉、RSI 阈值、BOLL 轨道位置 | 截图常见，通达信/i问财也提供技术形态选股；**当前漏斗规则注册表无这些求值规则**。需逐项定义公式周期、复权、交叉是否含等号、最少样本和可重放证据 | 一期后段，完成算法注册才显示“可运行” |
| 资金流 | 主力净流入 > 阈值或连续 N 日净流入 | 单日字段比较已有，但需 D10 精算档口径、水位与覆盖；连续 N 日需新序列规则 | 精算档验证后开放，默认关闭 |

“阶段新高”必须明确是收盘价、盘中最高价、成交量还是净利润的新高，以及是否把今天纳入 N 日；“平台整理/平台突破”“卖盘枯竭”“主力吸筹”没有统一计算口径时只作为**待澄清意图**，不可静默替换成某个指标。除示例一外，用户可以组合任意已注册且数据已就绪的条件，模型不得固定套用示例阈值。

## 5. 已发现的语义与数据缺口

1. **20 日新高存在可复现的少看一根问题**：`rule_rolling_high` 在 `lookback=20` 时用 `series[-20:-1]` 取前 19 根；`rule_close_new_high` 用 `series[-21:-1]` 取前 20 根。示例一原文说“收盘价创 20 日新高”，但 YAML 采用前者。落地时保留旧规则版本行为以免无提示改变历史模型，新建示例和文案编译应使用 `close_new_high(20)`；若选择迁移旧版本，需版本升级、差异预览和重放验证。现有示例文档关于新高的多处描述也需同步校正。
2. **“小于/不超过”“高开区间/至少高开”不能合并**：示例分别是 `<7%` 和闭区间 `[1%,2%]`。自然语言编译逐条保存比较符、上下界、单位与原文片段；不确定时请求改写或明确选择。
3. **数据层级独立于规则存在**：依据[数据同步规范登记册](../data/market-data-sync-specification.md)，D6 财务、D8 行业、D11 盘口/逐笔和 D10 精算资金流各有不同的采集与水位要求。登记册包含历史核验记录，不能替代本次运行的水位检查。任何缺失值均为 UNKNOWN/数据不足，不得当 0、PASS 或直接缩小全市场分母。
4. **示例四阶段也需时点校核**：示例 YAML 的 `market_gate` 在 `09:30–09:35`，而[示例文档](./selection-funnel-example-1.md)及[通用设计规范](./selection-model-general-specification.md)有“竞价后、开盘前终判”描述。F2 应明确采用哪种可观察且可执行的门控时点，并据此更新模板/文案/测试；不能同时声称两者已满足。
5. **当前目录不证明正式信号**：主数据、日线、资金流、指数现价、开盘和分钟点需按运行日期、股票全集及阶段候选逐层验收；盘中形态版不得解释为真实主动买卖盘供需确认。

## 6. 暂缓纳入一期可运行目录

| 条件簇 | 暂缓理由 | 后续准入条件 |
|---|---|---|
| 财务报表：毛利率、营收/净利润增长率、ROE、现金流等 | D6 报告期、披露日和“当时已知”数据契约未闭环，容易发生未来信息泄漏 | 完成报表字段/披露时点、缺报、追溯修订和样本外回放口径 |
| 行业、概念、地域、指数成分 | D5/D8 成分或分类快照的历史有效期和覆盖率需核对 | 明确分类版本、成分生效时点与运行全集覆盖 |
| 消息、公告、机构评级、热度/关注度 | 事件抽取与发布时间、去重、来源和全文证据尚无选股字段契约 | 结构化事件目录及可审计来源落地 |
| DDE 大单净额/净量、龙虎榜机构净额、专有资金标签 | 供应商定义和授权、历史可得性、口径可迁移性未核对 | 逐字段签订来源/单位/延迟/覆盖契约，不用其他资金流指标冒名 |
| 涨停接力、平台形态、复杂 K 线组合及自动评分 Top-N | 需要各自清晰公式或已执行排序节点；示例 Top-N 目前只是声明态 | 独立注册版本化算法，做边界样本与逐股证据验收 |

暂缓项仍可在自然语言输入中被识别为用户意图，返回“暂不支持/待定义”，不能悄悄丢弃。第二期扩展依据用户需求、数据接入成本与样本外验证排序，不以其他产品的菜单数量为目标。

## 7. 一期验收口径

- 用人工配置与中文输入各生成一次**相同四阶段**的未激活草稿，逐项比对原文片段、规则版本、参数/单位、逻辑关系、时窗、数据需求和定义哈希；示例一 YAML 与精确定义的差异须先显式裁定。
- 对范围、涨幅、市值、新高、MA、成交量、指数门控、高开、回调反转分别提供 PASS/FAIL/UNKNOWN 的固定数据样例；覆盖等号边界、少一根 K 线、缺市值、缺指数/分钟点和代理资金流。
- 同一运行使用已归档快照和全市场证券主数据分母；手工点击立即触发数据门禁与筛选，调度时点另算。数据不足时失败关闭并保留 `run_id/stage_id/rule_id` 与缺口证据。
- 新增 MACD/KDJ/RSI/BOLL 等 B 圈算法时，先更新规则/字段目录、确定性计算器、中文别名与版本，再开放 UI；目录收录本身不得作为可运行验收证据。
