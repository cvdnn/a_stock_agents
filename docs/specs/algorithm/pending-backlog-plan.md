## 二、batch2-decisions（未开始，阻塞于逐项裁定）

以下 6 项均出自规范 §26「待产品确认事项」，需用户逐项给出决策后才能实现；裁定前不得擅自选默认值。

### B1 · Web 启停权限（§26-6）

- **规范原文**：「Web 中谁有权激活策略和启停自动调度」。
- **待裁定**：激活策略 / 启停自动调度的角色边界（如：仅管理员、模型作者本人、全体登录用户）。
- **影响面**：Web 端权限模型、自动调度任务的鉴权链路。

### B2 · 通知渠道（§26-7）

- **规范原文**：「信号通知渠道采用 Web 站内、桌面 Toast 还是外部消息渠道」。
- **当前临时基线**：通知仅 Web 站内展示（§26 末段）。
- **待裁定**：首期渠道范围，是否引入桌面 Toast 或外部消息渠道。
- **影响面**：通知分发层、外部渠道凭据与失败重试策略。

### B3 · 跨维度分数引用（§26-8）

- **规范原文**：「条件模型首期是否允许跨维度引用派生分数，还是仅允许布尔结果引用」。
- **待裁定**：条件模型可引用的是「布尔结果」还是也包含「派生分数」。
- **影响面**：条件模型 DSL 的引用类型校验、编译期依赖图与循环引用检测。

### B4 · 模型可见性（§26-9 / §26-10）

- **规范原文**：「用户自建模型是否默认仅本人可见，后续是否支持模板共享和复制」；「模型名称是否允许重复；建议允许显示名称重复，但 `model_id` 必须全局唯一」。
- **待裁定**：默认可见性（仅本人 / 团队 / 全体）；是否支持模板共享与复制；显示名重复策略。
- **影响面**：模型注册表可见性字段、列表查询过滤、`model_id` 唯一性约束。

### B5 · T+N 标记价口径（§26-14）

- **规范原文**：「T+N 默认使用开盘、收盘还是 VWAP 作为标记价格；建议同时保存标准口径，但模型评价固定一个主口径」。
- **待裁定**：模型评价固定的主口径（开盘 / 收盘 / VWAP）。
- **影响面**：跟踪观察与模型评价结果的可比性；建议保留多口径存储、评价固定单一主口径。

### B6 · 评价最小样本量（§26-16）

- **规范原文**：「模型评价触发的最小样本数、最短观察周期和默认比较基准；上线前必须由研究治理规则确定」。
- **待裁定**：最小样本数、最短观察周期、默认比较基准三项。
- **影响面**：模型评价门禁与「简单优化建议」的触发条件（§26-19 要求建议可追溯到具体 `run_id` 与观察样本）。
