# 自然语言选股规则编译与次日信号运行方案（示例策略与扩展边界）

> 状态：受限中文文案到草稿链路已实现；第 1 节示例的次日实时阶段仍需接入和验收。本文记录当前能力与扩展任务，不代表任意新条件或实盘信号已经上线。
> 依托：`selection-system-specification.md`、`selection-model-general-specification.md`、现有 ISS v2 模型 Schema、规则注册表与版本仓库。
> 2026-10-12 新裁定：本计划中的 LLM 统一从项目「系统配置」读取 `quant` 角色绑定的 Provider/模型；现有单次 `model` 覆盖属于待整改实现。完整分期及准入条件见[智能选股漏斗板块重设计计划](intelligent-selection-funnel-redesign-plan.md) F2/F3/F6/F7。
> **范围说明**：第 1 节的条件和第 3 节的次日时窗只描述一个输入策略示例，不是所有用户模型的默认规则、固定阶段或强制筛选条件。

## 1. 示例策略的输入与精确定义（非固定条件）

以下仅说明用户提出“收盘后初筛、次日开盘回调确认”这套具体策略时，应如何把其原文还原成可验证规则。表中证券范围、MA60、30 亿、7% 等都是该示例的输入值；系统不能在其他用户创建模型时自动加上这些条件。该示例要求交易日 T 收盘后在同一数据版本求值，条件关系为 AND：

| 条件 | 确定性口径 | 数据依赖 |
|---|---|---|
| 沪深 A 股、非北交所 | 证券主数据 `market in {sh, sz}`；另保留显式排北交所谓词以展示原文映射 | 证券主数据 |
| 非 ST | 名称不含 ST，包括 `*ST` | 当日有效名称 |
| 20 日收盘新高 | `close[T] > max(close[T-20:T-1])`，需 21 根完整日 K；只比较收盘价 | 不复权/复权口径必须在同一快照中一致 |
| 站上 MA60 | `close[T] > mean(close[T-59:T])` | 60 根完整日 K |
| MA60 近 5 日上升 | `MA60[T] > MA60[T-5]`，需至少 65 根日 K | 同上 |
| 当日量大于昨日量 | `volume[T] > volume[T-1]`；不等同于“持续放量” | 2 日同单位成交量 |
| 主力资金净流入 | 当日供应商精确字段 `main_net_inflow > 0`；无数据或仅有代理值则不通过 | 资金流供应商、日期、来源标签 |
| 流通市值大于 30 亿 | `circulating_market_cap > 3_000_000_000` 元，严格大于 | 现有装配层取不晚于 T 的最近估值快照；超过 7 个自然日标记为过期，单位为元 |
| 当日涨幅不超过 7% | `change_pct <= 7`，恰好 7% 可通过 | 同交易日的前收与收盘 |

该示例的次日 T+1 流程为：指定基准指数在可用实时价格上方于其 MA20；9:30 开盘价相对前收高开至少 1%，没有高开上限；9:30–9:35 观察冲高后回调；9:35–9:40 用已定盘分钟数据确认卖压衰减、买盘增强，并输出满足条件的代码。未定义指数代码、分钟级数据字段或拐点阈值时，系统必须保留为待确认参数，不能让 LLM 推测并自动激活。该示例的时间按 Asia/Shanghai、交易日按交易所日历解释；候选池只用 T 日完整快照生成并冻结，T+1 不重新混入未过夜间筛选的股票。

### 新用户条件如何进入模型

- 用户每次提交的自然语言才是该模型的条件来源。LLM 将原文拆解为阶段、规则类型、字段、比较符、阈值、单位、时窗和条件关系的候选配置；服务端按原文逐项核对，预览无遗漏后由用户确认创建未激活草稿。发布版本固定规则配置，运行时由程序读取行情和逐股计算。
- 已注册规则中的可配置参数可按用户输入变化，例如均线周期、回看天数或已支持字段的阈值；只有编译器能够忠实映射且通过参数 Schema、数据依赖与计划编译时才可使用。用户调整参数无需把示例中的 60 日、30 亿或 7% 写入通用默认条件。
- 新的条件组合、阶段和时窗只有在 ISS 模型结构与调度器能够表达时才可发布。核心漏斗模型已经支持阶段级 `all/any` 与显式布尔表达式；自然语言编译器尚未安全映射这些关系。原文出现 OR 而文案编译器不能忠实生成对应表达式时，须标记不支持或待确认，不能改写为 AND。若出现尚未注册的新算法、数据字段或数据源，LLM 只能返回 `unresolved`；需先补齐规则实现、参数 Schema、字段来源/时点口径及验证，再由用户重新编译和确认，不能让 LLM 即时生成可执行代码或自行定义行情计算。
- **当前实现边界**：`llm_rule_compiler.py` 仍以 `INTENT_KINDS` 和逐类校验限定 10 种意图，部分参数可变、部分比较方向固定；最终只生成一个 `post_close` 阶段，默认将匹配规则按 AND 执行。因此它目前不能保证解析任意新选股条件，复合句也需防止只命中其中一部分却被标为 `complete=true`。后续应让自然语言映射层由已注册规则的能力与参数元数据驱动，并增加受控阶段/关系编译；未覆盖的语义须明确返回 `unresolved`，不得让模型猜测或静默省略。

### 通用编译器的目标设计与可行性

**结论**：采用“通用编译流程 + 有界规则能力目录”。通用表示用户可自由组合已注册的字段、运算符、阈值、时间窗口、阶段和逻辑关系；不表示 LLM 可现场发明数据字段、行情算法或执行代码。现有 `rule_registry.py` 已提供规则版本、参数 Schema 和所需输入，`schemas.py` / `model_compiler.py` 可把多阶段及 `all/any`、显式表达式编成计划，适合作为确定性后端。缺口在于自然语言语义映射、字段目录、数据时点校验和完整性验证，单靠扩大提示词不能解决。

| 设计路径 | 评估 |
|---|---|
| 继续逐条扩写 `INTENT_KINDS` 与 `_make_rule` 分支 | 可以短期补个别条件，但每新增语义都要改解析分支；阶段和逻辑关系仍容易遗漏，不适合作为通用方案。 |
| 让 LLM 直接生成规则代码或任意字段表达式 | 看似覆盖面广，但计算口径、数据来源、权限和回放不可控，不进入正式运行链。 |
| 让 LLM 绑定受控能力目录，程序编译与运行 | 推荐；需要先建设语义/字段元数据及完整性校验，但可复用现有规则引擎、版本和证据体系。 |

| 层 | 需要形成的通用契约 | 编译失败时 |
|---|---|---|
| 规则能力目录 | 对每个已注册规则补充中文别名、适用市场/阶段、参数语义与单位、比较方向、历史窗口需求；与计算实现的规则版本一致 | 未注册算法不进入草稿 |
| 字段与数据目录 | 列出字段 ID、类型、单位、交易日/分钟时点、来源、复权口径、最小历史量、缺失与过期策略；`field_ref` 不能仅凭字符串自由指向任意字段 | 字段或所需数据源不可用时列为待确认/不支持 |
| 中间意图 | LLM 只返回原文片段位置、原子条件、规则/字段 ID、参数、单位、阶段与时窗、`and/or/not` 关系及未解析项；服务端重新构建表达式树 | 条件或关系漏失、改写时不能标记 `complete=true` |
| 确定性编译 | 逐项验证原文字面量和单位、参数 Schema、字段白名单、阶段触发器及声明的数据时点要求，再调用 `normalize_definition`、`compile_definition`；实际快照覆盖率留给运行门禁检查，保存条款映射、规则版本和计划哈希 | 仅返回歧义/错误和预览，不保存、发布或激活 |

编译流程为：**用户原文 → 原子条件与逻辑关系 → LLM 候选中间意图 → 服务端能力绑定和语义校验 → 可审阅漏斗定义 → 已发布不可变计划 → 固定快照逐股执行**。原文与中间意图逐项保留证据：每个原子条件有原文位置、规则 ID、参数来源和归属阶段；`and/or/not` 也须有原文依据。当前“按标点拆句后比较条数”不足以证明复合句完整，需增加原子片段覆盖、否定词/逻辑词、数值单位及时窗一致性校验，并让用户在预览中确认。无法机器证明语义等价时保持歧义状态。

能力扩展分三类：① 已注册规则只变参数或阈值，可由通用编译自动处理；② 已注册规则的新组合、阶段或 OR/NOT，需生成合法表达式并通过调度/数据门禁；③ 新算法、新字段或新数据源，先由工程侧补齐计算、数据、元数据和测试，注册后再对 LLM 可见。这样新增用户条件不必复刻第 1 节示例，也不会把未实现能力伪装成可运行。

准入验证应以独立的中文文案语料覆盖同义改写、否定、并列/嵌套 OR、跨交易日、单位换算、同一句多个数字以及未知新条件。对可支持输入，比对人工配置的规则/表达式和同快照筛选结果；对不支持或语义有歧义的输入，要求不出现 `complete=true`。规则注册表与实际执行器的一致性、`field_ref` 的允许字段、布尔表达式遇到 `UNKNOWN` 时的行为及调度时窗，均须在隔离用例中验证后才开放对应能力。

## 2. LLM 规则编译运行契约

1. 用户经受鉴权的 `POST /api/selection-models/drafts/from-text` 提交中文文案与 `mode=llm`；服务端只能通过 `LLMProviderFactory.get_provider(role="quant")` 读取项目系统配置的 Provider/模型/凭据。未配置、停用或不可用时失败关闭，不接受本次请求覆盖模型，也不静默降级到 `chat`、环境默认模型或本地解析。现有接口与弹窗仍允许 `model` 标识，须在新工作台落地时整改并覆盖旧调用兼容测试。外部 LLM 只接收文案条件，不接收行情、账户或交易凭据。
2. 服务端先将并列条件拆成带序号的条款，限定输入长度和条款数量。LLM 只返回 `{clauses:[{id,kind,params,reason?}]}`。合法 `kind` 来自服务端白名单，无法判断必须返回 `unresolved`。
3. 确定性编译器对每个条款作编号、唯一性、数量、关键字、数字、单位、范围、规则参数和注册表验证。例如第 1 节示例里的 30 亿必须换算为 30 亿**元**；LLM 将用户写的 7% 改成 8% 时拒绝。每个条款恰好有一个去向；不允许略过未知条款再宣称完整。
4. 编译结果是带来源条款映射的 ISS v2 漏斗草稿。接口返回已匹配项、歧义项、模型与提示词版本、`complete` 和 `activated=false`。生成过程中不读行情、不输出股票代码、不保存用户模型、不发布版本、不启动调度。
5. 工作台只有在 `complete=true` 且无歧义时提供“创建草稿”；保存走既有 `createModel` + 带 `base_version`、`draft_revision` 的 `saveDraft`，编辑、校验、发布和激活仍走既有权限/版本流程。请求错误与超时不降级为假成功，也不会悄悄切换到本地正则结果。
6. 草稿最终经过 `normalize_definition` 和 `compile_definition`；正式运行只消费已发布计划及固定数据快照，不调用 LLM 再解释条件。计划哈希包含各规则语义版本。旧 `rolling_high` 已有历史语义，新增 `close_new_high` 单独注册，避免无迁移地改变旧发布版本。

### 对抗、歧义与资源上限

- 将原文视为数据；其中出现“忽略规则”“直接输出代码”等指令不作为系统指令。LLM 输出仅能声明白名单意图，由本地规则编译器重新验算。
- 缺字段、过期快照、未收完 K 线、数据源不符、参数超界、条款漏失、重复编号、非法 JSON、请求超时均失败关闭。不能拿代理资金流替换供应商“主力净流入”字段。
- 当前规则编译单次输入至多 4,000 字、40 条，响应至多 24,000 字、45 秒；编译请求仅发生在编辑时。未来盘中 LLM 判断属于另一个有独立时延、数据等级和样本外门禁的影子实验，不复用 45 秒编辑超时，也不替代规则引擎的逐股计算。
- 保留原文、模型标识、提示词版本、条款映射、草稿与计划哈希供审计；日志避免记录凭据或完整供应商响应。发布前应由具备权限的使用者核对数据口径与每条映射。

## 3. 示例策略的运行态状态机（非固定流程）

下表只对应第 1 节的收盘初筛与次日回调示例。其他用户模型的阶段、时窗、条件组合和数据要求由其已发布计划决定，不继承这些固定时间或阈值。

| 时间与状态 | 输入和前提 | 输出及失败行为 |
|---|---|---|
| T 15:35 后 `POST_CLOSE` | 同日完整日 K、主数据、精确资金流、估值快照，交易日一致 | 固定夜间候选池、规则轨迹和快照 ID；既有日线覆盖率不足则 `WAITING_DATA`，个股其他字段不足则该股 `UNKNOWN` 并被拒绝 |
| T+1 9:30 `INDEX_GATE` | 指定指数最新有效价格和 MA20，时间戳新鲜 | `index_price > MA20` 才进入开盘门；无指定基准或行情则停止 |
| T+1 开盘 `GAP_GATE` | 候选股正式开盘价、可比前收 | `gap_pct >= 1` 的子集；停牌、无正式开盘价、数据延迟剔除 |
| 9:30–9:35 `PULLBACK_OBSERVE` | 完整分钟 Bar，已出现冲高与回调 | 只更新观察态，不提前宣称拐点 |
| 9:35–9:40 `TURN_CONFIRM` | 已定盘 Bar、成交/盘口字段、量化阈值 | 卖盘衰减与买盘增强同时确认后输出代码、时点、证据；任一缺失则 `UNKNOWN` |
| 9:40 后 `CLOSED` | 窗口结束 | 不补发过时的买点；保存未命中原因 |

拐点应配置为可验证的谓词：先定义局部高点和最低回调幅度，再比较连续已定盘 Bar 的主动卖出量、主动买入量、买卖盘挂单变化与价格止跌确认。所需字段、窗口长度、阈值、数据供应商须在发布版本中固定；只能用数据实际提供的字段。若只有分钟 OHLCV，则不能把“卖盘枯竭”描述成已由买卖盘数据验证。信号输出仅为筛选结果，止损与交易执行属于既有独立流程。

建议新增模板的**待确认配置**如下；其中数值参考现有 `config/funnel_strategy.yaml` 的拐点规则，必须经回放调参，不能因出现在本文就成为默认正式信号：

```yaml
market_gate:
  schedule: "09:30-09:35"
  benchmark: "待确认指数代码"
  rule: {type: market_above_sma, period: 20, strict: true}
opening_gap:
  schedule: "09:30-09:31"
  rule: {type: field_compare, field: gap_pct, op: gte, value: 1.0}
turning_point:
  schedule: "09:35-09:40"
  rule:
    type: intraday_turning_point
    window_start: "09:30"
    pullback_end: "09:35"
    confirm_start: "09:35"
    window_end: "09:40"
    min_pullback_pct: 0.20
    max_pullback_pct: 2.00
    max_sell_ratio: 0.75
    min_buy_ratio: 1.20
    required: [pullback, price_reversal, sell_exhaustion, buy_strengthening]
    metric_policy: real_only_for_signal
```

模板正式落盘前，还须显式设置最少完整分钟数、回调/确认段样本数及发信号最早时刻；按现有规则注册表校验后方可发布。上方 `market_gate/turning_point` 是设计草案，**不是**可直接传入 ISS 的完整 v2 配置。

## 4. 现有 `a_stock_agents` 优化评估与落点

| 现状 | 风险 | 本次落点 / 剩余动作 |
|---|---|---|
| `catalog.draft_from_text` 只支持少量正则 | 完整策略漏项，本地“20 日新高”走旧 `rolling_high`，与要求的完整 20 个历史交易日不一致 | 新增 LLM 意图服务和确定性编译器；保留旧本地接口行为作兼容 |
| 规则引擎已有 MA、量比较、资金/市值字段、分钟拐点 | 无需让 LLM 重写计算逻辑 | 新增 `close_new_high` 与 `market_include`；夜间条件映射已有注册规则 |
| 装配层有资金来源、水位与交易日检查 | 缺证券市场字段会使沪深范围无法可靠判定 | 将 `stock_basic.market` 装配进记录；缺失时失败关闭 |
| 工作台文案弹窗只展示解析结果 | 用户无法将完整映射交给草稿仓库，也有 HTML 注入风险 | LLM 预览、转义文本、完整性门禁、创建未激活草稿 |
| 现有调度/拐点规则与样例模板 | 不能推断指定指数、盘口数据、拐点阈值已经满足该用户策略 | 下一阶段配置 T+1 指数门、无高开上限的 `gap>=1`、9:35–9:40 定盘时点，使用隔离历史样本验收 |
