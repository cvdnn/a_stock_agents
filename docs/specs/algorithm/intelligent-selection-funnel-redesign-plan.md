## 一、功能设计范围

| 功能 | 设计要求 |
|---|---|
| 菜单与入口 | 在【策略选股】紧下方新增平级【智能选股】菜单，保留菜单栏现有样式；【智能选股】只有一个侧栏入口，不设置【运行记录】子菜单。 |
| 策略选股 | 选择策略、设置单次参数、执行筛选、查看本次结果；结果不带智能选股模型版本和调度状态。 |
| 智能选股工作台 | 在同一工作区内以「选股记录 / 模型管理」两个 Tab 切换，默认打开「选股记录」。前者查看运行和逐层证据，后者管理模型草稿、规则、版本与调度。 |
| 首期模型 | 仅开放漏斗模型的创建与运行；保留其他类型的既有资料和接口。用户可手工配置规则，或将中文条件编译为待核对的未激活草稿。 |
| 运行与结果 | 已发布计划基于固定本地数据快照逐层筛选；各阶段显示输入、通过、淘汰、未知及规则证据，支持结果检索、分页和导出。 |

## 二、工作台信息架构与用户流程

```text
项目侧栏（沿用现有设计，两个平级导航项）
├─ 策略选股：选择现有策略 → 设置单次参数 → 执行 → 查看本次结果
└─ 智能选股（单个菜单入口）
   ├─ 工作台 Tab「选股记录」（默认）：运行列表 → 运行详情（逐层漏斗 + 当前层候选与证据）
   └─ 工作台 Tab「模型管理」：漏斗模型列表 → 新建/编辑 → 校验、发布与版本管理
```

1. 侧栏【策略选股】保留 `selection` 菜单代码、文字、图标和现有样式；紧接其后新增同级【智能选股】一级导航项、独立 pane 和工作区。两个菜单各自独立点击、独立活动态；侧栏宽窄态、键盘焦点沿用现有导航约定。原 `SelModels.bootstrap()` 只在进入【智能选股】时调用。
2. 【策略选股】优先接已有的一次性 5A 筛选能力，按单次运行呈现：策略名、参数、执行时点、数据来源和水位、结果及失败原因。F0 核对实际 CLI/任务接口后再决定其他可用策略；开发期间若 HTTP 接线尚未完成，该页明确展示“暂不可执行”及原因，不能用样例结果代替，且不视为双板块交付完成。
3. 【智能选股】工作台内以「选股记录 / 模型管理」两个 Tab 组织功能，默认打开「选股记录」。前者展示真实运行列表，点击记录在同一 Tab 查看运行详情；后者管理漏斗模型草稿、规则、版本和调度。沿用现有 `runs/models` 状态切换，只将「选股列表」改名为「选股记录」，不另建侧栏子菜单或第三个「运行记录」Tab。新建时直接选择 `funnel`，无需显示无关类型。列表、最近运行、新建选股对话框、文案建模、深链接与模型切换均限定漏斗类型；访问旧的其他类型详情时显示明确的类型不适用提示，不修改旧模型。限制是本工作区的产品范围，不等于删除后端 `condition_tree` 契约。
4. 模型编辑视图采用规则库、漏斗阶段画布、属性抽屉；运行详情展示模型上下文、纵向阶段和当前层候选。编辑与运行有独立标题、操作和空态，不共用“运行中”状态描述。
5. 所有运行结果绑定同一 `model_id`、发布版本、`run_id`、`stage_id` 和数据快照。阶段显示输入/通过/淘汰/未知/透传、数据水位和时间；候选筛选、分页与 CSV 导出同一查询口径。缺失行情显示“未记录/未提供”，不补默认价格。
6. 草稿、发布/激活、调度器在线、手工运行及运行失败分别显示；手工同步运行无取消能力时不出现“停止运行”操作。未完成 D-11 数据门禁时只允许如实展示观察候选和失败关闭结果，不宣称正式信号可用。

### 自然语言规则编译功能设计

**入口与输入**：在「模型管理」的“新建漏斗模型”流程提供“用自然语言描述规则”。用户输入中文条件，可描述股票范围、收盘筛选、次日指数/开盘门控、回调观察和确认时窗；阶段间先后、AND/OR 关系、比较符、阈值、单位、交易日及数据口径必须在预览中显式呈现。核心漏斗计划支持阶段级 `all/any` 和显式表达式，但现有自然语言编译器还不能忠实生成 OR/NOT；不能表达的关系必须标记“不支持”，不得擅自改成 AND。未写明的基准指数、回调幅度、买卖盘字段或确认阈值均列为待确认项，不能由模型补猜。输入用于创建规则草稿，此时不读取行情、不筛股票、不启动调度。现有单次输入上限为 4,000 字、40 条；扩展多阶段时需重新验证条款拆分与资源上限。

**解析与受控编译**：服务端以 `mode=llm` 接收文案，将原文拆为编号条款，调用项目「系统配置」中 `quant`（算法量化）角色绑定的 Provider、模型和服务端凭据，经 `LLMProviderFactory.get_provider(role="quant")` 提取结构化意图。每条意图包括原文编号、目标阶段、注册规则类型、字段、比较符、参数值与单位、时窗/数据等级；暂不能解释的条款返回 `unresolved` 及原因。LLM 只提供候选意图，服务端逐条复核编号覆盖、原文数字/单位、字段与比较符、参数范围、规则注册表、阶段触发器和数据依赖，再经定义规范化与编译校验生成漏斗草稿。模型不得生成 SQL、Python、股票名单或执行代码。现有实现仅支持少量收盘条件并产出一个 `post_close` 阶段；跨 T/T+1 阶段与更多组合关系须在 F2 完成注册、编译和测试后才作为可用能力展示。

规则条件以当前用户文案为来源，不预置某一套示例策略的证券范围、均线、阈值或次日时窗。LLM 可以为**已注册、已具备数据口径的规则**选择参数并编排可执行阶段；新增算法或数据字段须先纳入规则注册表、计算实现和数据契约，再开放给文案编译。无法表达的条件返回 `unresolved`，不自动变成固定示例条件。

通用编译采用“规则能力目录 + 字段与数据目录 + 原文片段/逻辑关系中间表示 + 确定性校验”。规则能力目录由已注册规则的版本、参数 Schema、输入需求扩展中文别名、单位和阶段约束；字段目录限定字段 ID、来源、时点和新鲜度。LLM 只选择目录内的规则及参数，服务端校验原子条件和 `and/or/not` 的原文覆盖、数值单位、数据依赖及表达式结构，最后调用既有模型编译器。未知算法、字段或不完整复合句保留 `unresolved`，不能仅凭“条款数量一致”认定完整。

例如，原文“流通市值大于 30 亿元，涨幅不超过 7%”应拆成两条，分别预览为“流通市值 > 3,000,000,000 元”和“当日涨幅 ≤ 7%”，并显示所处阶段、数据字段及对应规则。若解析成 8%、把“收盘新高”改为盘中最高价，或漏掉任一条款，服务端拒绝完整编译。用户说“卖盘明显减弱”却未指定可验证字段、时窗和阈值时，预览显示待确认，不能自动生成可发布的盘中规则。

**预览、确认和保存**：预览页按“原文条款 → 阶段 → 受控规则 → 参数/单位 → 数据需求”逐项展示，并集中列出未匹配、歧义和不可执行条件；用户可改写原文后重试，或进入规则编辑器手工补齐。只有条款全部覆盖、无歧义、阶段与数据契约可编译时，才可点击“创建草稿”。确认后保存的是未发布、未激活草稿；具备相应权限的用户仍须编辑核对、校验、发布和激活。发布版本固定规则与计划哈希，运行只消费已发布计划及对应数据快照；模型配置变化或同一句文案再次解析，不会暗改已发布版本。

预览响应须明确给出原文条款及映射、歧义列表 `ambiguities`、完整性 `complete`、草稿定义、实际使用的 Provider/模型及提示词版本，并标记 `activated=false`；解析成功只代表可创建草稿，不代表模型已发布、数据已经齐备或已经产生选股结果。编辑后保存继续使用现有草稿修订号与版本冲突检查。

**失败与审计**：未配置 `quant`、Provider 停用、超时、无效 JSON、条款漏失、单位变化、非法规则或所需字段未注册可用数据源，均显示具体错误或待确认状态，不回退到其他模型、默认本地解析或伪成功。工作台不设置独立 API Key/供应商/模型标识；单次请求的 `model` 覆盖须由服务端拒绝。记录原文、条款映射、已解析的 Provider ID/模型 ID、提示词版本、草稿/计划哈希及校验结果，不记录凭据。已存在的本地解析模式若保留，应作为用户显式选择的独立模式呈现，不冒充 LLM 编译成功。

### LLM 结果解释与盘中判断边界

1. **逐股筛选与结果解释**由程序基于同一已归档快照、已发布计划和规则引擎完成。LLM 只可将持久化的 `failed_rules`、`unknown_rules`、`observed`、`expected`、`reason_code` 组织为可读解释；逐条引用 `run_id/stage_id/rule_id`，缺失证据标“未记录”，不得推测价格、阈值或候选。解释失败不更改筛选结果。
2. **盘中 LLM 判断**作为独立影子实验：仅对确定性条件筛出的回调候选发送带 `snapshot_id`、事件时间、字段 ID 与数据等级的结构化特征；模型可返回 `BUY/WAIT/REJECT` 和引用证据，但影子回包不改变候选、正式信号或交易动作。程序校验 JSON Schema、代码/时间/输入哈希、证据 ID、快照新鲜度及最新行情；自然语言失效条件需转成注册的可执行谓词。超时、缺字段、回包晚于窗口或证据不实均记为“未评估/无效”，不得按淘汰或买入处理。
3. 是否让盘中判断影响正式结果，须预先登记纯规则对照组、同批同刻样本、模型/提示词冻结版本、延迟与费用预算，以及含 T+1、成交限制、手续费和滑点的样本外评价方法。只有证明净效果相对纯规则基线有稳定增益，并通过 D-11/M-03/M-05 适用的数据与发布门禁后，才另行评审启用；批量大小、响应时限和结果有效期均按影子运行实测确定。重新请求 LLM 属于新实验；历史重放使用已归档原始回包。

### F0 · 基线与契约

- [ ] 记录当前 `HEAD`、工作树、侧栏入口、原工作台功能、菜单种子和 `selection.*` 权限矩阵；以隔离身份/临时模型确认已有接口能力，不读取或修改用户现有模型。
- [ ] 核对 `astock screen --json` 与 `screen_5a` 的真实参数、同步/异步行为和结果字段，设计一次性策略筛选 API 契约及失败关闭行为；明确与 `/api/selection-models` 的数据/权限隔离。
- [ ] 以 `funnel` 模型跑通“创建草稿→保存→校验→发布→选择版本运行→逐层查看”隔离基线，记下真实缺口；不将旧测试结果当本次证据。
- [ ] 明确新平级菜单 `intelligent_selection` 的查看权限与既有 `selection.*` 模型动作权限的组合及角色兼容迁移；核对存量自定义角色，不能让原有授权用户无故失去访问，也不能让普通用户因新菜单获得模型写权限。
- [ ] 用隔离配置核对 `quant` 角色、Provider 启用状态与能力读取路径；记录文案弹窗/接口允许 `model` 覆盖、规则编译只产单个 `post_close` 阶段的待改项，不读取生产密钥或调用真实模型。收盘阶段的启动时间以数据齐备和现有 15:35 水位门禁为准。

### F1 · 菜单与独立工作区

- [ ] 保持左侧 `.nav-item[data-tab="selection"]` 的文字、图标、位置、样式及 `selection` 菜单码不变；在 DOM 与菜单种子中紧随其后只新增一个 `parent_id=0` 的【智能选股】一级项和独立 pane，处理各自活动态、键盘焦点及页面标题；不创建【运行记录】子菜单，不使用子菜单缩进或展开控件。
- [ ] 把现有 `SelModels` DOM/事件完整迁至【智能选股】pane，且只保留一份工作台；切换时处理未保存草稿提示、过期请求与旧运行详情，避免两个板块共用当前模型状态。
- [ ] 将工作台内部 `runs/models` 切换呈现为「选股记录 / 模型管理」两个 Tab，默认选中「选股记录」；Tab 的列表、标题、按钮和空态随模式一致切换。运行详情仍在「选股记录」内打开；从「模型管理」离开时提示未保存草稿。
- [ ] 分离两页顶栏动作：策略侧仅显示真实策略操作，智能侧仅显示模型相关操作；删除“导出接口尚未实现”这类与实际运行详情不一致的顶栏状态。
- [ ] 新菜单的可见性与服务端权限一致：模型接口保留 `selection.*` 动作码，同时增加 `intelligent_selection` 查看门禁；为已有授权角色做幂等迁移，核对直接请求 API 不能绕过权限。原策略筛选另有独立操作权限。

### F2 · 首期只开放漏斗类型

按[第一期条件选股规则目录](../../guidelines/algorithm/selection-condition-rule-catalog.md)先闭合示例一 A 圈，再逐项开放主要通用条件 B 圈；每项分别核对规则注册、字段白名单、运行数据和文案编译，不以菜单项存在作为可运行证据。

- [ ] 模型查询使用 `model_type=funnel`；最近运行提供服务端类型过滤及准确 `total`，确保数量/分页也只算漏斗运行，不在前端拿 50 条后过滤。
- [ ] 「选股记录」展示运行实例，不以模型卡片冒充运行记录；「模型管理」展示模型资产，两个 Tab 的计数、搜索与空态各按自身数据口径呈现。
- [ ] 新建向导、中文文案建模、已发布版本选择、重复运行、模型/运行详情直达均校验 `funnel` 类型；不能把非漏斗定义交给漏斗画布或静默转换。
- [ ] 复用现有版本、草稿并发冲突、服务端 `selection.*` 权限和作者本人模型激活规则；仅收窄该板块入口，不破坏已有条件树 API/数据。
- [ ] 为类型不适用、无权限、无本地数据、数据水位未就绪、无模型与无运行分别设计可见空态/错误态。
- [ ] 文案解析只使用系统配置的 `quant` 模型：移除工作台临时模型标识输入，服务端拒绝 `mode=llm` 的单次 `model` 覆盖，并登记对旧调用的兼容性处理；无量化角色、Provider 停用或结构化输出不可用时给出可操作错误，不回退到其他模型或伪成功。
- [ ] 建立面向自然语言编译的规则能力目录和字段目录，与现有规则注册表、运行实现及数据契约核对版本和覆盖关系；补齐中文别名、参数单位、允许字段/比较符、时窗及所需数据，不让 LLM 自行扩充规则 ID 或字段 ID。
- [ ] 将现有逐条 `kind/params` 编译扩展到漏斗阶段意图：按用户原文绑定收盘、次日指数/开盘门控、回调确认等可执行阶段的时窗、字段、数据等级与缺失策略；仅允许已注册规则和合法触发器。将文案映射与规则注册表的参数 Schema、所需数据及语义版本关联，避免把某套示例条件写成通用模板。以复合句漏项、20 日新高、MA60 五日斜率至少 65 根完整日 K、资金流供应商口径、百分比和市值单位为边界用例，并覆盖新增已注册规则与未知新规则；歧义未确认不发布。

1. 左侧【策略选股】的视觉、菜单码和导航层级不变；紧下方新增同级【智能选股】菜单，两者均为 `parent_id=0` 且各有独立活动态。侧栏没有【运行记录】子菜单；【智能选股】工作台内恰有「选股记录 / 模型管理」两个模式 Tab，前者默认选中。两个独立工作区的标题、操作、权限和数据语义清楚区分。

3. 漏斗编辑、版本发布、手工运行、逐层追溯、搜索分页、导出和错误反馈组成可复现闭环；每个数值都能追溯到指定运行及数据时点。
