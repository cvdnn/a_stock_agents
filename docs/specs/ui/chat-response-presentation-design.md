# AI 会话回复分层呈现与执行轨迹设计

**状态：** 已批准设计，待实施计划

**日期：** 2026-09-11

**适用范围：** Web AIChat 对话卡片、SSE 执行事件、右侧详情区、异常反馈

## 1. 背景与目标

当前 AI 回复把模型返回的 Markdown 原文直接写入会话卡片，导致标题、列表、表格和代码块按源码显示；长报告挤占对话流；`thought`、工具调用和异常状态只覆盖一行状态文本，用户无法回看任务过程和子任务结果。

本次改造采用“核心摘要 + 执行轨迹 + 右侧完整详情”的分层结构：

1. Markdown 以安全、可读的格式渲染。
2. 会话卡片只保留提炼后的核心结论，长报告进入右侧详情区。
3. 会话卡片内持续展示主任务及子任务执行轨迹，每个子任务可展开查看本次执行结果。
4. 异常属于任务轨迹的一部分，在对应失败节点内反馈；技术详情按需展开。
5. 沿用系统现有白色系、蓝色主色和轻量边框风格，不复制参考截图的深色视觉。

## 2. 非目标

- 不改变后端任务规划、工具选择或模型路由语义。
- 不增加第二次大模型调用来生成摘要。
- 不在本次改造中新增任务取消、重新编排或跨会话任务恢复。
- 不把完整报告重复保存在多个 DOM 区域。
- 不通过外部 CDN 引入 Markdown 运行时依赖。

## 3. 已选方案

采用方案 C：会话卡片展示核心摘要与执行轨迹，右侧展示完整 Markdown 报告、证据和长诊断信息。

相较于“卡片内折叠全文”，该方案避免长报告破坏对话节奏；相较于“仅摘要 + 右侧全文”，它保留了模型思考、工具调用、降级和失败的可追踪性。摘要由同一次模型回复在浏览器本地按确定性规则提取，不增加模型成本和等待时间。

## 4. 信息架构与交互

### 4.1 会话卡片

AI 卡片从上到下包含：

1. 标题、标的及生成状态。
2. 执行轨迹摘要，例如“4/5 个步骤完成，1 项降级”。
3. 可展开的执行轨迹。
4. 渲染后的 Markdown 核心结论，目标为 3–5 条关键内容。
5. “查看完整分析”按钮，打开或聚焦右侧详情标签。
6. 复制与重新生成等既有操作。

完整模型文本不直接铺在会话卡片中。流式阶段显示稳定的内容占位与执行状态；收到 `done` 后生成摘要并替换占位，避免每个 token 都引起整卡重排。

### 4.2 执行轨迹

执行轨迹由本次 SSE 会话中的事件顺序构建，不能用新事件覆盖旧事件。轨迹节点至少支持：

- `thought`：规划或推理说明。
- `tool_call_start`：子任务开始。
- `tool_call_complete`：子任务成功、降级或失败，并绑定执行结果。
- `error`：模型或任务失败。
- `done`：本次会话完成。

每个子任务节点是独立的可展开控件：

- 折叠态显示名称、状态图标、耗时或简短结果摘要。
- 展开态显示该次调用的格式化结果；结构化对象以键值或安全代码块呈现，文本结果以安全 Markdown 呈现。
- 同一工具多次调用形成多个节点，不覆盖前一次结果。
- 运行中节点显示轻量进度，不使用造成布局抖动的动画。
- 成功、降级和失败同时使用图标、文本与颜色表达，不能只依赖颜色。

轨迹默认折叠。失败时自动展开轨迹并展开首个失败节点；其他节点保持用户最后的展开状态。

### 4.3 右侧详情区

点击“查看完整分析”时，复用现有 `openRightTab` / `switchRightTab` 能力创建或聚焦与该条回复绑定的详情标签。标签至少包含：

- 完整分析：渲染后的模型 Markdown 全文。
- 数据证据：本次工具调用产生的结构化结果和来源信息。
- 异常详情：仅在存在失败时显示，提供完整错误码、原始安全错误信息和修复建议。

右侧详情与会话卡片共享同一个回复状态对象。卡片摘要、轨迹节点和右侧全文通过回复 ID 关联，不复制业务状态。重复点击同一回复只聚焦已有标签，不创建重复标签。

### 4.4 异常反馈

异常信息必须出现在会话卡片的执行轨迹中，而不是在任务卡片外新增独立错误横幅。

失败节点的折叠态显示面向用户的摘要，例如“模型请求失败，点击查看诊断详情”；展开态显示：

1. 可理解的失败原因。
2. 明确恢复建议，例如检查角色绑定、服务地址或模型能力后重试。
3. 稳定错误码与 HTTP 状态（如存在）。
4. 可复制的技术详情，但不得包含 API Key、认证头或其他敏感值。

错误节点使用系统语义危险色、边框和失败图标，正文仍保持可读对比度。节点使用 `role="alert"` 或等价的 `aria-live` 语义通知辅助技术，但展开动作不抢夺当前输入焦点。

## 5. 前端组件边界

在保持现有原生 HTML/CSS/JavaScript 技术栈的前提下，把职责拆为以下小单元：

### 5.1 MarkdownRenderer

- 输入：不可信 Markdown 字符串。
- 输出：经过转义、白名单转换和链接协议校验的 HTML。
- 支持：标题、段落、强调、列表、引用、行内代码、代码块、链接和表格。
- 禁止：原始 HTML、事件属性、`javascript:`/`data:` 等危险链接协议。

流式文本只进入内存缓冲区；最终或节流后的渲染统一经过该组件，禁止再次直接把模型文本赋给 `innerHTML`。

### 5.2 ResponseSummarizer

- 输入：完整 Markdown 文本。
- 输出：3–5 条核心结论及可选关键位行。
- 优先级：明确的“核心结论/结论/建议/风险”章节，其次是列表项和强调句，最后回退到前几个有效段落。
- 去除 Markdown 装饰后去重；每条设置长度上限，保留完整原文作为详情来源。
- 无法提取时显示第一段有效正文，不产生空卡片。

### 5.3 ExecutionTimeline

- 维护有序节点集合和调用 ID 到节点的映射。
- 负责事件追加、状态转换、结果绑定、耗时显示和展开状态。
- 未匹配到开始事件的完成/失败事件仍生成可诊断节点，不能静默丢弃。

### 5.4 ResponseDetailView

- 根据回复 ID 渲染完整分析、证据和异常详情。
- 与现有右侧标签生命周期对接。
- 在回复仍流式生成时可显示实时进度，完成后替换为最终安全 Markdown。

### 5.5 ErrorPresenter

- 将后端错误码映射为用户文案与恢复建议。
- 保留未知错误的稳定兜底文案和脱敏技术详情。
- 只负责呈现，不改变任务成功/失败语义。

## 6. 客户端状态模型

每条 AI 回复建立独立状态对象：

```text
responseId
status: streaming | succeeded | failed
fullMarkdown
summaryItems[]
timelineNodes[]
toolResultsByCallId
errors[]
detailTabId
metrics: elapsedMs, tokens, finishReason
```

轨迹节点至少包含：

```text
nodeId
type: thought | tool | error | done
title
status: pending | running | succeeded | degraded | failed
startedAt / completedAt / elapsedMs
summary
result
error
expanded
```

该状态只存在于对应回复生命周期中。DOM 元素保存回复 ID，不保存完整 JSON 字符串。

## 7. SSE 数据流

1. `conversation_start` 创建回复状态、空轨迹和右侧详情上下文。
2. `thought` 追加推理节点或更新同一活动推理节点。
3. `tool_call_start` 创建运行中的子任务节点，并记录调用 ID。
4. `tool_call_complete` 按调用 ID 完成节点，绑定结果和状态。
5. `content_delta` 只追加到 `fullMarkdown` 缓冲区，并以节流方式刷新右侧预览；不把原文直接铺入会话卡片。
6. `error` 完成对应节点；若无调用 ID，则追加模型/会话级失败节点，自动展开轨迹并停止成功态收尾。
7. `done` 计算本地摘要、完成指标、渲染卡片，并刷新右侧最终内容。

如果当前后端事件缺少调用 ID、结果或状态字段，前端按事件顺序做兼容关联；实施计划可补充向后兼容字段，但不破坏现有 SSE 事件名称。

## 8. 视觉与可访问性约束

- 复用现有白色表面、蓝色主操作和轻边框；错误使用语义红色，降级使用警示色。
- 采用 4/8px 间距节奏；展开按钮具有不小于 44×44px 的有效点击区域。
- 可交互节点使用真正的 `button`，维护 `aria-expanded`、`aria-controls` 和可见焦点环。
- 展开/折叠使用 150–300ms 的透明度或位移动画，避免动画化高度导致持续重排；支持 `prefers-reduced-motion`。
- Markdown 表格在窄屏进入局部横向容器，不能让整个页面横向滚动。
- 正文对比度至少 4.5:1；成功、降级、失败均有文本标签和一致的 SVG 图标。
- 不引入远程字体或图标依赖，避免离线失败和首屏布局偏移。

## 9. 安全设计

- 所有模型正文、工具结果和错误详情均视为不可信输入。
- Markdown 渲染先转义 HTML，再执行受控语法转换；链接仅允许 `http:`, `https:` 和 `mailto:`，外链增加安全的 `rel` 属性。
- 工具结构化结果使用文本节点或转义后的代码块，不拼接可执行 HTML。
- 错误详情在进入 DOM 前执行既有或新增的敏感字段脱敏，覆盖 API Key、Authorization、Cookie 和常见令牌格式。
- 复制操作复制原始 Markdown 或已脱敏技术详情，不复制 DOM 注入内容。

## 10. 兼容与降级

- 没有轨迹事件但有正文时，卡片仍能显示摘要和完整分析入口。
- 没有工具结果时，子任务展开区显示“本次调用未返回可展示结果”，而不是空白。
- 右侧详情区不可用时，“查看完整分析”降级为卡片内的按需展开全文，但默认仍保持折叠。
- 历史消息若只有正文，按相同 Markdown 与摘要规则渲染，不伪造执行轨迹。
- 未识别错误码显示通用失败文案，并保留脱敏详情供诊断。

## 11. 测试与验收

### 11.1 单元测试

- Markdown：标题、列表、表格、代码、链接、嵌套格式与危险 HTML/协议。
- 摘要：优先章节、列表去重、长度限制、中文标点和无可提取内容回退。
- 轨迹：事件顺序、多次同工具调用、完成前无开始事件、降级、失败和展开状态。
- 错误：已知错误映射、未知错误兜底和敏感信息脱敏。

### 11.2 DOM/交互测试

- AI 卡片不再显示原始 Markdown 标记。
- 点击子任务可展开本次执行结果，再次点击可折叠。
- 点击完整分析只创建一个右侧标签并可重复聚焦。
- 异常节点位于会话卡片执行轨迹内，失败时自动展开。
- 键盘可完成所有展开、切换和打开详情操作，ARIA 状态同步。

### 11.3 SSE 集成测试

- 验证完整事件序列、只有正文、工具失败、模型失败、缺少调用 ID 和连接中断。
- 验证错误后不会显示“模型响应已结束”的成功状态。
- 验证子任务结果与正确调用节点绑定，不被后续事件覆盖。

### 11.4 人工验收

- 使用真实已配置模型生成包含标题、列表、表格和代码的长回复。
- 验证会话区只显示核心内容，右侧完整内容无缺失。
- 验证成功、降级和失败任务的展开结果与视觉层级。
- 验证 375px、768px 和桌面宽度，不出现页面级横向滚动。
- 验证服务端异常提示与参考交互一致，但保持项目统一浅色风格。

## 12. 完成标准

- 回复 Markdown 安全渲染且无原始语法堆叠。
- 会话卡片稳定显示 3–5 条核心结论，完整报告可在右侧查看。
- 所有已收到的任务/工具事件在执行轨迹中可回看。
- 每个子任务可展开查看本次结果。
- 异常在对应会话卡片的执行轨迹中反馈，并提供可操作恢复建议和脱敏详情。
- 现有复制、重新生成和右侧标签行为无回归。
- 自动化测试与真实服务人工验收通过。
