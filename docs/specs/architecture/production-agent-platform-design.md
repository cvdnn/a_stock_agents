# A-Stock Agents 正式 Agent 平台与真实能力执行设计

**状态：** 已批准设计基线  
**日期：** 2026-09-10  
**适用范围：** Web AIChat、统一 CLI、项目级 Skills、MCP 接入、任务执行、多智能体协作、真实数据投射与跨宿主运行

**实施状态：** P0“真实性与安全止血”已完成并设回归门禁；P1–P7 仍待实施。本状态不代表整个平台已达到第 18 节正式运行标准。

## 1. 背景与目标

当前 Web 工作台存在三类生产阻断问题：运行时默认使用 Mock 模型，聊天入口显式传入 `mock`；部分 REST 接口返回固定演示数据；前端在接口失败后静默回退到高保真 Mock。由此产生的界面虽然完整，但无法证明数据、工具执行和最终结论来自真实链路。

本设计把现有项目能力升级为正式 Agent 平台，同时保持原有“零全局污染、技能就地运行、统一 CLI、宿主解耦”原则。目标是：

1. 用户请求必须先通过已配置且可用的大模型完成意图理解与任务规划。
2. 所有量化、行情、风控、股池、报告和交易能力统一通过项目 Skills 执行。
3. MCP 用于外部数据源和辅助能力的接入、发现、授权、调用与健康管理。
4. 任务执行系统按主任务与辅助任务传播失败，禁止把失败或旧数据混入最终分析。
5. 多智能体仅围绕成功取得的证据协作，最终结论由配置的大模型整合生成。
6. Web、Hermes、Codex、Antigravity 和其他宿主复用同一套 Skills、CLI 和 JSON 契约。
7. 正式运行路径不允许 Mock、硬编码行情或静默伪造成功。

## 2. 非目标

- 不重写 `scripts/core/` 中已有量化算法和数据桥。
- 不把 Web 数据库、大模型配置或 FastAPI 变成 Skills 的运行依赖。
- 不以 MCP 复制现有 Skill 能力或建立第二套量化实现。
- 不在本轮接入实盘券商下单；有副作用的模拟交易仍受现有确认门禁约束。
- 不用“返回 unavailable”冒充能力已经完成；未接通的能力保持不可用状态。

## 3. 架构原则

### 3.1 Skill 是业务能力的单一真理来源

项目能力以 `.agents/skills/<skill-id>/SKILL.md`、`config/skills_manifest.json` 和统一 CLI 为契约。正式执行必须解析规范 Skill ID、校验参数 Schema，并调用对应的 `astock <subcommand> --json` 或其同一核心处理函数。

FastAPI 路由、Web 组件、任务 Worker 和多智能体不得直接复制 `DataBridge`、指标算法、保本计算或报告生成逻辑。它们只能通过统一 Skill 执行适配器消费结果。

### 3.2 MCP 是外部能力接入层

MCP 主要用于接入项目外部的数据和工具，例如新闻、政策、舆情、基本面数据库、公告检索或其他辅助信息。MCP 能力进入统一注册中心后，与 Skill 共用权限、参数、超时、审计和结果封装，但保留 `source_type=mcp` 身份。

项目自有量化能力继续以 Skill/CLI 为主。后续可以提供入站 MCP Facade，把已治理的项目能力暴露给支持 MCP 的外部宿主，但该传输层不能替代 Skills，也不能成为 Codex/Hermes 独立运行的前置条件。

### 3.3 Web 是宿主，不是业务内核

Web 模式提供模型配置、会话、任务编排、SSE 状态和结果展示。外部 AI 宿主使用自身模型完成意图理解与整合，并直接调用项目 Skills/CLI。两种模式共享业务能力与输出契约，但不共享宿主特有的模型凭据和会话数据库。

## 4. 分层架构

系统由七层组成：

1. **交互层**：Web AIChat、CLI、Hermes、Codex 等宿主接收用户提示词。
2. **模型门禁层**：验证 Web 配置的模型供应商、角色、模型、认证与连通性。
3. **意图与规划层**：识别用户主意图，生成具有依赖关系和失败级别的任务 DAG。
4. **统一能力层**：`CapabilityRegistry` 聚合 Skill 与 MCP 描述，`SkillExecutor` 和 `MCPExecutor` 分别执行。
5. **任务运行层**：负责状态机、并发、超时、安全重试、取消、确认、持久化和审计。
6. **多智能体协作层**：按数据、技术、基本面、政策、消息、资金、筹码和风控角色处理证据。
7. **证据整合与展示层**：过滤失败结果，由配置模型生成最终答案，并通过 SSE/A2UI/报告展示。

依赖方向必须保持从宿主到能力层再到 `scripts/core/`，核心层不得反向导入 `scripts/server/`。

## 5. 正式请求数据流

### 5.1 Web 模式

1. 接收用户提示词并写入会话，但尚不创建业务任务。
2. 模型门禁按角色解析实际供应商和模型，执行配置完整性与连通性检查。
3. 门禁失败时终止请求，返回可诊断异常，不运行任何量化任务。
4. 门禁成功后，大模型依据用户提示词、Skill/MCP 能力清单和权限信息生成任务 DAG。
5. 任务规划器校验 DAG：主任务必须存在；依赖不可成环；参数符合能力 Schema；写操作具有确认要求。
6. 任务执行器按依赖并行执行 Skill 与 MCP 节点，并保存来源、时间、状态和审计信息。
7. 任一关键节点失败时终止任务；辅助节点失败时标记为 `omitted`，不向融合上下文传入其旧数据、空壳数据或占位值。
8. 所有关键节点成功后，把成功证据和辅助缺失清单交给配置模型进行最终整合。
9. 模型整合失败时整项任务失败，不回退到模板文本。
10. Web 通过 SSE 展示真实状态，并把最终答案、来源和缺失板块写入会话。

### 5.2 外部宿主模式

Hermes、Codex、Antigravity 或 Claude Code 在项目工作区中读取 `.agents/skills` 和 `AGENTS.md`，使用宿主自身的大模型规划任务，通过统一 CLI 的 `--json` 输出执行能力。它们不需要启动 FastAPI，也不读取 Web 的供应商配置。

Skill 的错误、来源和时间契约必须足以让外部宿主执行与 Web 相同的主次失败决策。宿主可以使用项目提供的任务规划提示词规范，但不依赖 Web 的 Python Agent Runtime。

## 6. 统一能力注册与执行

### 6.1 CapabilityRegistry

注册中心保存统一元数据：

- `capability_id`：规范 Skill ID 或 MCP 工具 ID。
- `source_type`：`skill` 或 `mcp`。
- `actions`：能力支持的操作，例如 quote、tech、evaluate、report。
- `input_schema` 与 `output_schema`。
- `permission_level`：只读、写入、交易或外部传输。
- `availability`：可用、禁用、未配置、连接异常或未实现。
- `dependencies`：所需内部能力、MCP 连接或数据源。
- `timeout_seconds` 与安全重试策略。

注册中心不保存业务结果，也不直接执行工具。它为规划器提供经过权限过滤的能力视图，并为执行器提供解析后的调用描述。

### 6.2 SkillExecutor

SkillExecutor 负责规范 ID/别名映射、参数校验、治理门禁、统一 CLI/核心处理函数调用、超时控制和审计。Web 现有 `server.agent.tools` 必须迁移为此适配器的薄入口，不能绕过 `SkillRegistry`。

所有 Skill 结果使用统一 `ExecutionResult`：

```json
{
  "status": "success|error|unavailable|timeout|confirmation_required",
  "capability_id": "astock-data-feed",
  "action": "quote",
  "source_type": "skill",
  "source": "tencent",
  "fetched_at": "2026-09-10T09:30:00+08:00",
  "data": {},
  "error": null,
  "metadata": {}
}
```

只有 `status=success` 的 `data` 可以进入后续分析。

### 6.3 MCPManager 与 MCPExecutor

MCPManager 管理服务器配置、凭据引用、启停状态、连接健康、工具发现缓存、权限与调用审计。MCPExecutor 只调用注册且已授权的工具，并把返回值转换为同一 `ExecutionResult`。

辅助 Skill 可以在 Manifest 中声明 MCP 数据依赖，但不得在 Skill 内硬编码某个 Web MCP 连接。执行时由宿主根据依赖选择可用能力并注入结果，保证 Skill 在无 Web 环境下仍可使用 CLI 或由外部宿主提供等价数据。

## 7. 模型配置与就绪门禁

Web 模型选择优先级为：用户本轮显式选择、会话显式偏好、业务角色绑定、系统默认角色。禁止隐式回退到 Mock。

任务开始前必须确认：

- 供应商存在且已启用。
- Base URL、模型 ID 和角色映射完整。
- 需要认证的供应商已有后端密钥。
- 连接测试和最小模型请求成功。
- 所选模型满足工具调用或结构化输出要求；不满足时明确阻断。

供应商列表 API 只返回 `has_api_key`，不返回密钥正文。前端不在 localStorage 保存供应商密钥。空密钥更新表示保留既有密钥；测试连接、获取模型和任务执行通过 `provider_id` 在后端取凭据。CORS 默认仅允许本机受信来源。

## 8. 用户意图与任务 DAG

意图分析采用“大模型语义规划 + 本地确定性校验”双层结构。现有 `IntentEvaluator` 可作为交易意图提示和规则校验，不能单独替代模型对复杂提示词的理解。

任务节点至少包含：

- `task_id`、`capability_id`、`action` 和参数。
- `criticality`：`critical` 或 `optional`。
- `depends_on`：前置任务列表。
- `agent_role`：处理结果的角色。
- `timeout_seconds` 与允许的安全重试次数。
- `purpose`：该节点如何服务用户主意图。

规划器必须明确一个主任务目标。系统本地校验器有权拒绝无主任务、引用未知能力、参数非法、形成环或绕过确认门禁的计划。

## 9. 任务执行系统

任务状态为 `planned`、`blocked`、`running`、`succeeded`、`failed`、`omitted`、`cancelled` 或 `confirmation_required`。任务运行记录保存在用户隔离的 `output/cache` 数据库中。

只读、幂等的数据请求可按配置进行有限重试；交易、写股池、归档和其他有副作用操作不得自动重试。超时后的任务必须可取消，不能继续在后台产生写入。

主任务所需的关键能力失败时，运行进入 `failed`，停止所有尚未开始的依赖任务，并在会话中返回异常代码、失败能力、原因和修复建议。辅助能力失败时进入 `omitted`，其失败摘要可以进入最终提示，但其业务数据不能进入融合上下文。

## 10. 多智能体协作

多智能体是任务图上的证据消费者，不是任意访问底层模块的独立脚本。每个角色只接收完成职责所需的成功证据：

- 数据 Agent：检查数据来源、时间和完整性。
- 技术 Agent：消费行情、K线和指标 Skill 结果。
- 基本面 Agent：消费财务 Skill 或 MCP 结果。
- 政策与消息 Agent：消费公告、政策、新闻和舆情 MCP 结果。
- 资金与筹码 Agent：消费资金面与筹码 Skill 结果。
- 风控 Agent：消费持仓、费用、止损和风险 Skill 结果。
- 综合 Agent：只整合各角色的结构化结论和缺失清单。

角色模型来自系统设置中的业务角色绑定。纯数值计算不调用大模型。角色之间通过结构化证据和结论通信，不共享未经审计的完整上下文，防止失败数据或提示注入横向扩散。

## 11. 错误语义与用户提示

模型门禁错误包括 `LLM_NOT_CONFIGURED`、`LLM_AUTH_FAILED`、`LLM_MODEL_UNAVAILABLE`、`LLM_CAPABILITY_UNSUPPORTED` 和 `LLM_TIMEOUT`。这些错误发生时不创建业务任务。

关键节点失败返回 `TASK_CRITICAL_DEPENDENCY_FAILED`，会话必须说明失败接口或 Skill、错误摘要、已完成节点和建议动作。系统不得调用另一个模型或模板伪造最终结论。

辅助节点失败返回 `TASK_OPTIONAL_DATA_OMITTED`。最终报告必须列出未取得的板块、来源和原因，并声明该板块未参与融合分析。

无持仓、空股池和未启动监控属于真实空状态，不等同接口失败。界面应分别显示“暂无数据”或“未启动”，不能生成示例持仓或在线状态。

## 12. 正式模式与 Mock 隔离

正式运行默认启用 production 模式：

- 禁止注册或选择 `MockLLMProvider`。
- 删除前端 `api.js` 的运行时 Mock 返回和模板打字机成功回退。
- `market_data.py` 不再返回固定行情、资产、事件和分析结论。
- 未接通的能力返回结构化 unavailable。
- UI 显示真实空状态、配置错误或接口错误。

Mock Provider、合成行情和固定报告仅保留在测试夹具或显式 test 模式。测试数据必须带 `synthetic=true`，且 test 模式不能与用户正式数据库和端口复用。

## 13. 工作台数据投射

市场、股池、持仓、监控和报告卡片不直接绑定静态 REST 对象，而是投射任务或 Skill 的 `ExecutionResult`。工作台可发起只读系统任务，例如“市场概览”，其主任务和辅助数据依赖仍遵循同一失败语义。

暂时没有真实 Skill/MCP 支持的板块保持 unavailable，直到对应能力通过真实性验收。所谓“AI 研判”必须引用本次任务成功证据并由配置模型生成。

## 14. 安全与审计

- 模型和 MCP 凭据只在服务端存储与解析，API、日志、SSE 和前端状态均不得返回正文。
- 外部 MCP 返回内容视为不可信数据，只作为证据输入，不得覆盖系统指令或授予权限。
- 每次能力调用记录调用者、会话、任务、能力、参数摘要、来源、耗时、状态和错误；敏感字段脱敏。
- 写入、交易和外部传输能力继续执行 Human-in-the-loop 确认，并防止确认重放。
- 用户持仓、会话、报告和审计记录继续限定在 `output/`。

## 15. 优先级与依赖顺序

### P0：真实性与安全止血

禁用正式 Mock、移除静默回退和硬编码成功；增加模型门禁；修复供应商密钥返回、localStorage 和 CORS；校准失实的完成状态。该阶段完成后，系统可以“不好看地失败”，但不能继续伪造成功。

实施结果（2026-09-10）：已完成。正式模式拒绝 Mock；模型门禁先于工具执行；供应商凭据不再经 API/浏览器存储返回；默认 CORS 为显式本地来源且不携带凭据；未接通的 Skill/REST/UI 路径返回 unavailable/error/empty；`tests/test_production_authenticity.py` 提供持续扫描。P1 的统一 Skill 执行契约及其后阶段不在本结论内。

### P1：统一能力注册与 Skill 执行

统一规范 ID、别名、Schema、权限、状态和审计；所有 Web 工具调用经过 SkillRegistry/SkillExecutor；建立 `ExecutionResult`。复用现有整改计划 R1 与 R2a。

### P2：用户意图和任务规划

建立模型驱动的意图分析、任务 DAG Schema、本地计划校验和关键性标记。没有通过模型门禁时不进入该阶段。

### P3：任务执行系统

扩展现有 TaskManager，支持 DAG、依赖调度、并发、取消、超时、安全重试、确认暂停、失败传播、SQLite 状态和 SSE 事件。

### P4：MCP 接入与辅助数据

建立 MCPManager、连接配置、健康检查、工具发现、权限、凭据引用和 MCPExecutor；先接入能补足新闻、政策、舆情和基本面的数据能力。MCP 故障按任务节点关键性处理。

### P5：多智能体协作与角色模型

把现有 7 角色分析迁移到结构化任务和证据输入，按角色解析实际模型；隔离上下文；建立风控与综合仲裁。复用现有整改计划 R3、R4 和可用的 `core/multi_agent` 资产。

### P6：真实工作台与报告闭环

把市场、股池、持仓、监控、分析和报告页面改为真实任务结果投射；逐项接通已有 Skill 后端；未实现能力保持 unavailable。复用 R2b 与 A2UI 整改任务。

### P7：跨宿主与生产验收

验证 Windows/Linux/macOS 的统一 CLI JSON 契约；在无 Web 服务情况下完成 Codex/Hermes 技能调用；验证 Web 与外部宿主使用同一输入时得到同构执行结果；完成生产模式无 Mock/硬编码扫描和端到端故障测试。

## 16. 测试与验收策略

实施必须采用测试先行。测试分为：

1. **契约测试**：Skill/MCP 输入输出、错误状态、来源和时间字段。
2. **模型门禁测试**：未配置、禁用、认证失败、超时、能力不足和成功路径。
3. **任务 DAG 测试**：环检测、主任务失败、辅助任务遗漏、取消、超时和安全重试。
4. **治理测试**：禁用技能、参数非法、确认重放、超时后无后台写入。
5. **多智能体测试**：角色只接收成功证据；遗漏板块不参与结论；角色模型绑定生效。
6. **安全测试**：API/SSE/日志无密钥；前端无凭据持久化；MCP 内容不能改变权限。
7. **前端测试**：错误、空状态、遗漏提示和 SSE 状态准确，不显示伪成功。
8. **跨宿主测试**：CLI、Web、Codex/Hermes 的 Skill 结果契约一致。
9. **生产真实性测试**：扫描正式源码和构建产物，阻止 Mock 行情、固定账户、模板分析和 `model='mock'`。

单元与集成测试使用显式合成数据和 Fake Provider，不访问付费模型或真实账户。生产联调单独运行并记录接口、时间和数据来源；合成测试通过不能替代生产真实性验收。

## 18. 完成标准

只有同时满足以下条件，系统才能声明进入正式运行：

- 正式模式无法选择 Mock，源码和构建产物无运行时硬编码数据回退。
- 未配置或异常模型会在会话中中断并给出明确错误。
- 所有 Web 业务调用经过受治理的 Skill/MCP 能力层。
- 主任务失败终止，辅助任务失败被排除并在最终结果中披露。
- 最终结论由实际配置模型基于成功证据生成。
- 供应商和 MCP 密钥不会通过 API、日志、SSE 或浏览器存储泄露。
- 工作台每个已启用板块都有真实能力来源与验收证据；其余板块明确 unavailable。
- 在不启动 Web 的情况下，Codex/Hermes 仍能通过项目 Skills 和统一 CLI 完成受支持任务。
- 全量离线回归、相关前端测试、生产配置联调和跨宿主验收均有可复现记录。
