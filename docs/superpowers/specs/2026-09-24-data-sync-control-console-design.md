# 数据同步一级菜单三页控制台设计规范

## 1. 目标与范围

将现有 `数据同步` 一级菜单重构为与系统原生视觉一致的全宽控制台，并提供三个同级 Tab：

1. `运行控制`：查看真实同步状态、发起分级同步、检查数据源与完整性。
2. `任务记录`：查询真实异步任务、筛选状态、查看任务详情、取消运行中任务和重试失败任务。
3. `高级设置`：管理同步策略、定时守护、数据源顺序、完整性策略和本地存储信息。

本次同时落实“系统设置/配置类功能无需 AI 助手”的产品规则。进入 `datasync` 时，主工作区占满 AI 助手原有区域；标题栏不显示 AI 助手入口；页面不创建对话上下文，不调用模型，也不保留数据同步专属的 Copilot 问候语和快捷提问。

## 2. 非目标

- 不重构其他业务一级菜单的 Copilot 行为。
- 不修改同步引擎的 K 线抓取、校验或 SQLite 落盘算法。
- 不新增网络爬虫或绕过统一数据同步引擎。
- 不使用静态成功数据、随机延迟或 `setTimeout` 伪造任务完成。
- 不将本地设置、日志、数据库或任务运行数据纳入版本控制。

## 3. 现有系统一致性

页面复用 `web/css/style.css` 的现有语义 Token 和组件节奏：

- 左侧栏：现有 `190px` 白色导航，`数据同步` 使用品牌蓝激活态。
- 工作区标题栏：现有 `50px` 高度、白底、底部 `1px` 微边框。
- 画布：`#F8FAFD` / `var(--bg-canvas)`。
- 卡片：白色或 `#FAFCFE`，`1px solid var(--border-card)`，`8px` 圆角和轻量阴影。
- 主色：`var(--primary)`；成功、警告、失败分别使用现有绿、橙、红语义色，并同时配文字或图标，禁止只依赖颜色。
- 数字：任务时间、耗时、百分比、代码、延迟和计数统一使用 `.tabular-nums`。
- 图标：数据同步新增结构性图标使用同一套内联描边 SVG，不使用 Emoji 充当导航或按钮图标。
- 动效：150–300ms，支持 `prefers-reduced-motion`，不通过宽高动画造成布局抖动。

## 4. 信息架构

```text
数据同步（一级菜单）
├── 工作区标题栏
│   ├── 数据同步控制台 / 本地行情数据运维
│   └── 当前 Tab 对应的确定性操作
├── 运行控制
│   ├── 服务状态与关键指标
│   ├── P0/P1/P2 分级同步任务
│   ├── 数据完整性概览与修复入口
│   ├── 行情源健康度
│   ├── 自动守护摘要
│   └── 最近任务日志
├── 任务记录
│   ├── 当日任务统计
│   ├── 日期、任务类型、状态和关键字筛选
│   ├── 真实任务列表
│   └── 单任务参数、结果、错误和生命周期详情
└── 高级设置
    ├── 基础同步策略
    ├── 定时守护
    ├── 数据源优先级
    ├── 完整性与自愈
    ├── 本地存储
    └── 外部协同
```

Tab 切换只改变 `#pane-datasync` 内部内容，不创建新的一级路由，不改变左侧一级菜单激活状态。当前 Tab 保存于前端状态，并在同一会话内恢复。

## 5. 页面设计

### 5.1 运行控制

首屏使用 `4 个状态卡 + 主次双栏`：

- 状态卡展示服务状态、本地标的数量、最近一次真实同步时间和待处理异常数。
- 主栏展示 P0 持仓、P1 自选关注和 P2 核心指数。每个任务行包含范围、计划、当前水位和独立同步按钮。
- 完整性卡展示审计总数、健康度、合规停牌和异常缺漏。结果不可用时显示“尚未执行体检”，不得展示示例数字。
- 次栏展示真实数据源状态、守护设置摘要和最近 `data_sync` 任务；数据不可用时显示可恢复空状态。
- 顶部唯一主操作为“同步选中范围”，完整性体检为次操作。

### 5.2 任务记录

任务数据来自现有 `/api/tasks`，前端只展示 `task_type` 为 `data_sync` 或 `sync` 的记录：

- 顶部统计由返回的任务列表现场聚合，不硬编码。
- 列表字段：开始时间、任务名称、同步范围、模式、结果、状态、耗时和操作。
- 详情面板展示任务 ID、触发方式、参数、生命周期时间、结果摘要和错误原因。
- `pending/running` 任务可取消；`failed/timed_out/cancelled` 任务可使用原参数重新提交；`completed` 任务可再次执行。
- 运行中任务采用有限轮询刷新；离开 Tab 或没有活动任务时停止轮询。
- 空列表展示“暂无数据同步任务”，并提供“前往运行控制”操作。

### 5.3 高级设置

高级设置采用左侧配置域导航和右侧表单，不使用弹窗承载主配置流：

- 基础策略：默认模式、并发数、重试次数、超时秒数。
- 定时守护：总开关、P0 与 P1 执行时间。
- 数据源优先级：腾讯、新浪、东方财富、本地 SQLite 的排序与启用状态。
- 完整性与自愈：自动审计、异常缺漏自动回补开关。
- 本地存储：数据库相对路径、WAL 状态和日志路径，只读展示。
- 外部协同：保留通达信导入入口；导入操作不混入基础同步策略。

设置保存在 `local/settings/data_sync.json`，通过工作区 `PROJECT_ROOT` / `LOCAL_DIR` 解析，禁止硬编码绝对路径。服务端进行字段白名单、数值范围和 `HH:MM` 时间格式校验。前端显示未保存状态；保存成功后以服务端回读值为准。定时守护读取该配置，禁用时不得触发自动同步。

## 6. 数据与接口

### 6.1 复用接口

- `POST /api/tasks`：提交 `task_type=data_sync` 的同步任务。
- `GET /api/tasks?limit=...`：读取任务记录。
- `GET /api/tasks/{task_id}`：读取任务详情和进度。
- `DELETE /api/tasks/{task_id}`：取消活动任务。

### 6.2 新增确定性接口

- `GET /api/data-sync/overview`
  - 返回市场阶段、同步元数据聚合、股池数量、最近同步任务和有效设置摘要。
  - 无数据时返回 `null` / 空数组和明确的 availability 字段，不返回演示数据。
- `GET /api/data-sync/settings`
  - 返回经过服务端默认值合并与校验的有效设置。
- `PUT /api/data-sync/settings`
  - 保存白名单设置到 `local/settings/data_sync.json`，返回最终有效设置。

接口错误必须返回稳定的错误信息；前端保留原值并展示可重试提示，不得以“保存成功”掩盖失败。

## 7. 交互状态与错误处理

- 所有提交按钮在请求期间禁用，并显示加载态，防止重复任务。
- 成功、局部降级和失败统一使用系统右下角 Toast；错误信息包含原因和恢复动作。
- 列表、状态卡和设置表单均提供加载骨架、空状态和失败状态。
- 危险或影响全局的操作（取消任务、恢复默认设置、关闭守护）需要二次确认或明确的影响提示。
- 任务提交后立即切换到真实任务 ID 的运行状态，并通过任务接口刷新；不使用随机数模拟进度、延迟、健康度或成功结果。
- 页面切换时保留筛选和滚动位置。

## 8. AI 隔离规则

- `switchRightTab('datasync')` 强制保持工作区全宽，但不显示 `#btnCopilotLauncher`。
- `TabCopilotConfigs` 移除 `datasync` 配置。
- 数据同步页不调用 `askAboutRightContent`、`executeQuickAction`、聊天提交或模型选择逻辑。
- 进入其他业务页后，现有 Copilot 行为不受影响。
- 自动化测试必须断言数据同步页面不存在可见 AI 助手入口，且切换到该页不会生成数据同步欢迎消息。

## 9. 响应式与可访问性

- 桌面宽屏：运行控制使用主栏 + 290px 次栏；任务记录使用表格 + 详情栏；设置使用配置域导航 + 表单。
- 小于约 1024px：次栏和详情栏落到主内容下方；设置导航改为横向或双列区域导航。
- 小于约 768px：指标卡两列，表格允许容器内横向滚动，但页面本身不产生横向滚动。
- 所有按钮具备可见 `:focus-visible`，图标按钮提供 `aria-label`。
- Tab 使用 `role=tablist/tab/tabpanel` 和 `aria-selected`，键盘方向键可切换。
- 任务状态、完整性结果和数据源健康度不以颜色作为唯一信息。

## 10. 代码边界

- `web/index.html`：替换 `#pane-datasync` 为三 Tab 语义结构，保留稳定 DOM ID 给测试与行为绑定。
- `web/css/style.css`：新增以 `datasync-` 为前缀的样式，复用现有 Token，避免影响其他工作区。
- `web/js/api.js`：增加任务与数据同步设置/概览 API 方法。
- `web/js/app.js`：新增数据同步控制器、真实任务轮询、筛选、Tab 状态和设置表单逻辑；删除模拟随机数据与数据同步 Copilot 配置。
- `scripts/server/api/data_sync.py`：新增独立的数据同步概览与设置路由，并在服务端应用中注册。
- `scripts/server/app.py`：定时巡检读取有效数据同步设置。
- `tests/frontend/`：三 Tab 结构、无 AI、交互状态、真实 API 调用和失败恢复测试。
- `tests/server/`：设置校验、持久化隔离、概览真实性和定时守护设置测试。

## 11. 验收标准

1. 数据同步仍是左侧一级菜单，并与现有系统视觉无偏离。
2. 三个 Tab 均可访问、可键盘切换并保持选中状态。
3. 数据同步页在任何状态下都不显示 AI 助手按钮或对话面板。
4. 页面不含随机测速、随机健康度、伪造任务或定时成功提示。
5. 手动同步通过 `/api/tasks` 创建真实 `data_sync` 任务，任务记录能读取并跟踪它。
6. 失败任务可重试，活动任务可取消，空状态和错误状态均有恢复入口。
7. 高级设置经服务端校验后保存到 `local/settings/data_sync.json`，并影响定时守护行为。
8. 所有运行时数据仍位于 `local/`、`log/` 或既有数据库，不进入 Git。
9. 前端相关 Node 测试和后端 Pytest 均通过。
10. 在常见桌面宽度及窄屏下无页面级横向滚动，无交互元素被遮挡。
