# 数据同步工作台旧内容删除设计

## 目标

以 `docs/images/21_27_35.png` 为“数据更新”页的唯一视觉基准，删除当前页面中仍残留、且目标图未包含的旧版内容项。保留新版工作台的页头、页签、状态条、三张摘要卡、数据覆盖表、最近更新与自动更新。

## 已确认删除范围

- 分级标的池增量同步（P0、P1、P2 卡片）
- 同步今日快照入口
- P3 全市场同步控制区与进度区
- 多线程下载并发度滑块
- 数据连续性体检与智能自愈
- 行情源诊断与链路探测
- 服务内巡检与 CLI 守护日志
- 通达信文件导入

第二张附件中的全部可见内容均属于上述删除范围。

## 保留范围

- 数据同步工作台页头及“数据修复”“一键更新”操作
- “数据更新”“更新记录”“同步配置”三个页签
- 数据状态条、数据覆盖/待更新/异常缺失摘要卡
- 数据覆盖与更新状态表
- 最近更新卡片
- 自动更新卡片
- “更新记录”和“同步配置”页签现有内容
- 后端同步、审计、修复、P3、设置等能力与 API；本次仅收敛“数据更新”页可见内容

## 实施方案

采用直接删除旧 DOM 与仅服务于这些 DOM 的前端绑定/样式/测试断言的方案。对仍被保留页签或新版卡片使用的函数、API 和样式不做删除。

未采用的方案：

1. 仅用 CSS 隐藏：会留下不可达控件和维护负担。
2. 同时删除后端能力：超出本次视觉重规划范围，并可能破坏“同步配置”和 API 调用方。

## 页面结构结果

“数据更新”页按目标图收敛为：状态条 → 三张摘要卡 → 数据覆盖表 → 最近更新/自动更新。页面不再渲染任何旧版高级运行控制、诊断或导入内容。

## 兼容与错误处理

- 清理已删除元素的直接事件绑定和初始化访问，避免空元素导致运行时异常。
- 保留共享数据加载与状态刷新逻辑；允许其继续为摘要卡、覆盖表、最近更新和自动更新提供数据。
- 不改变服务端任务互斥、设置持久化和同步执行语义。

## 验证

- 静态检查 `web/index.html` 不再包含已确认删除项。
- 更新前端测试，使其断言目标结构存在且旧内容不存在。
- 运行数据同步相关前端测试与受影响的服务端测试。
- 在本地页面渲染后与 `docs/images/21_27_35.png` 对照，确认页面无旧内容残留、控制台无空元素异常。
