# 用户反馈验证流程 (absorbed from skill: user-feedback-verification)

> This file was consolidated from the now-archived `user-feedback-verification` skill.

## 问题背景

用户在提供市场观察或策略反馈时，表述可能是**主观感受而非客观事实**（如 "个股都小步上涨"）。将未经验证的用户反馈直接写入策略文档会导致分析偏差。

## 验证流程

当用户提供主观市场观察时，按以下流程处理：

```
收到用户反馈
    ├─ 识别反馈类型
    │   ├─ 客观数据（"上证4100点"）→ 直接引用，标注数据源
    │   ├─ 主观观察（"个股小步上涨"）→ 需验证
    │   └─ 策略建议（"不能等1.5倍右侧"）→ 需验证
    │
    ├─ 验证步骤
    │   1. 明确可验证的断言是什么
    │   2. 获取相关真实数据
    │   3. 对比断言与数据是否一致
    │   4. 如果不一致，修正表述为数据对应的结论
    │
    └─ 输出结果
        ├─ 断言正确 → 引用，标注验证方式
        ├─ 部分正确 → 引用修正后的版本，注明边界条件
        └─ 不正确 → 谢绝反馈，给出数据依据
```

## 可信度标签规范

每个输出数据点附带的标签格式：

```text
[可信度:高/中/低 | 数据源:东方财富/新浪/腾讯 | 时效:实时/5分钟前/日盘后]
```

| 置信度 | 含义 |
|--------|------|
| 高 | 数据源稳定、实时、与官方一致 |
| 中 | 数据源可用但有一定延迟，或非官方源 |
| 低 | 数据源不稳定、数据缺失、或推算得到（须注明原因） |

## 扩展验证模式：量化LLM交叉验证

当量化评分和 LLM 分析都对同一标的可用时，使用**融合评分矩阵**做交叉验证，产出单一共识评级：

| 量化评级 | LLM决策 | 共识 | 置信度 |
|:--------:|:-------:|------|:------:|
| A | BUY | 强烈买入 ⭐⭐⭐⭐ | 高（双确认）|
| B | BUY | 谨慎买入 ⭐⭐⭐ | 中 |
| C | BUY | 评分分歧 ⭐ | 低（需人工介入）|
| 任一方 | SELL | 一致离场 | 高（触发止损）|

**验证要点**：
- 当量化与 LLM 一致时（如 A+BUY），置信度定为"高"
- 当量化与 LLM 分歧时（如 C+BUY），置信度降为"低"，输出标注"存在分歧"
- 当 LLM 输出 SELL 时，无论量化评级如何，尊重离场信号

**数据源**：量化评分来自 `trading-combo` 的 100 分制框架，LLM 决策来自 `ta-multi-agent-analysis` 的 Portfolio Manager。
