## FIFO vs 移动加权平均验证方法

用户补充交易记录后，需用两种成本核算方法验证告知成本的合理性:

### FIFO法 (先进先出)
- 用 `collections.deque` 模拟批次队列
- 买入: `deque.append([shares, price, date])`
- 卖出: 从队列头部消费，`remaining > 0` 时说明超卖(缺更早建仓)
- 最终剩余批次的加权平均 = FIFO成本

### 移动加权平均法
- 买入: `avg_cost = (avg_shares * avg_cost + new_shares * new_price) / (avg_shares + new_shares)`
- 卖出: `avg_shares -= sell_shares` (成本不变)
- 最终 `avg_cost` = 剩余持仓的加权成本

### 判断券商使用哪种方法

| 现象 | 判定 |
|------|------|
| 减仓后成本骤升(如49.39→84.85) | FIFO法: 卖出低价筹码, 剩余高价底仓 |
| 减仓后成本小幅下降(如43.379→42.714) | 移动加权平均法 |
| 减仓后成本不变 | 未操作 或 两种方法结果相同 |

### 反推缺失建仓成本(移动加权平均法)

当告知成本已知、缺失建仓股数X已知时:

```
(已知买入总成本 + X * P) / (已知买入总股数 + X) = 告知成本
→ P = (告知成本 * (已知总股数+X) - 已知买入总成本) / X
```

案例: 600760缺失1400股, 告知成本42.7140
- 已知买入: 500@46.75 + 500@46.91 + 1000@39.26 + 1000@39.30 = 3000股, 总成本125,390
- P = (42.714 * 4400 - 125390) / 1400 = 44.68

## 数据可靠性分界点评估方法

### 核心方法: 双向验证

**反向溯源(从告知仓位倒推)**: 以用户直接告知的仓位为锚点(如7/30=3000股)，逐笔倒推每笔交易之前应有的持股数。若出现负数，说明该笔交易之前缺少建仓记录。

**正向验证(从最早交易正推)**: 从已知最早交易开始正推，看是否能与告知仓位对上。若正推结果 > 告知仓位，说明中间有卖出遗漏；若 < 告知仓位，说明缺少建仓。

### 反向溯源操作

```python
shares = told_shares  # 锚点仓位
for date, action, qty in reversed(trades):
    if action == "sell":
        before = shares + qty  # 卖出前应有更多
    else:
        before = shares - qty  # 买入前应有更少
    shares = before
    if before < 0:
        print(f"❌ {date}: 不可能(负数)")
```

### 正向验证操作

```python
shares = 0
for date, action, qty in trades:
    if action == "buy":
        shares += qty
    else:
        shares -= qty
    if shares < 0:
        print(f"❌ {date}: 超卖")
print(f"推算最终: {shares} vs 告知: {told}  差: {told - shares}")
```

### 分界点判定规则

1. 找到三只股票各自的自洽分界点(正向推算与告知仓位一致的时间点)
2. 取三者的最晚时间点作为统一分界点
3. 分界点之前的数据可能不完整，分界点之后的数据全部可靠

### 桥接验证(两个告知仓位之间)

当有两个时点的告知仓位(如7/30和7/31)时，验证期间交易能否桥接:

```
告知仓位A - 期间卖出合计 = 告知仓位B ?
```

若匹配 → 期间的交易记录完整 ✅
若不匹配 → 期间有遗漏的交易 ❌

## 关键经验

1. **session_search的bookend包含大量上下文** — 不需要逐条翻阅消息
2. **HTML报告文件是重要补充** — 部分交易记录只在HTML中存在(如7/30用户修正提示)
3. **仓位百分比可以精确反推总账户** — 但历史报告中的"~70%"可能是粗略估计
4. **FIFO成本变化可推断原始建仓结构** — 通过加权均价反推原始建仓批次
5. **非交易时段API返回0** — 收盘后腾讯API返回price=0, 需用报告中的收盘价
6. **bs4可能未安装** — 用re.sub(r'<[^>]+>', '\n', html) + html.unescape替代BeautifulSoup
7. **双向验证是定位数据断点的核心方法** — 反向溯源找负数断点，正向验证找差额
8. **K线可验证历史价格是否存在** — 用不复权K线检查告知成本是否为真实成交价
9. **桥接验证确认两个告知仓位间的交易完整性** — 告知A - 期间卖出 = 告知B
10. **移动加权平均可反推缺失建仓成本** — 但需注意是推测值而非实际成交记录
11. **000400成本微差0.005/股来自交易费用** — 佣金5元+过户费0.21元计入成本, 无需作为缺漏处理
